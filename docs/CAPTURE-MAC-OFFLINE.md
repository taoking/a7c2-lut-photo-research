第四十九轮新增 `lutphoto/capturemac.py`、`capturemsc.py` 和 [11 成员来源清单](../research/upstream-host.lock.json)。依据 QAQLeonard 固定 v2.1 内 ma1co 的 MSC/Sony 协议，以及继承的 Mac 接管设计；来源、完整许可见[致谢](../ACKNOWLEDGEMENTS.md)。只发布新增主机代码和来源指纹，不发布认证密钥或设备材料。

**这是尚未接入采集入口的内部绑定。** 本轮只向代码注入自制系统/PyUSB 形状对象，没有执行真实枚举、系统命令、全局锁、接口操作或相机查询。导入模块不会加载 USB。没有新增 CLI；旧安装器和原厂 2.01 完整程序门槛不变。

## 固定身份查询

查询显式执行以下五个 MSC 事务，不实例化会隐式初始化的旧 MscDevice，也不借服务模块识别机型：

| 顺序 | 固定操作 | 数据上限 |
| --- | --- | --- |
| 1 | TEST UNIT READY，六字节零 CDB | 无数据，读 13 字节 CSW |
| 2 | INQUIRY 头 | 5 字节 |
| 3 | INQUIRY 全体，长度为上一响应第 5 字节加 5 | 32–255 字节；厂商 Sony |
| 4 | Sony `0x7a`、外命令 1，写入型号请求 | 8192 字节；16 字节扩展头中的命令 1、方向 0 |
| 5 | 同一外命令读取型号信息 | 至多 8192 字节，至少 16 字节扩展头 |

CBW 为 31 字节，固定 tag 0、LUN 0；每个事务必须读到完整 13 字节 CSW。完整查询有 14 次底层收发：6 写、8 读。所有发送要求精确 int 完整长度，读取只接受 bytes 或精确 `array('B')`，先检查长度再转换；明确传递最长 5 秒及共享期限剩余时间。

CSW 签名、tag、residue 和状态均检查。短型号响应仅在 residue 等于请求长度减实际数据长度时接受。**tag/residue 一致性是新增、尚未实机验证的保守轮廓；固定上游仅检查签名/状态，不能宣称上述限制已被机身证明。** 完整错误不发 REQUEST SENSE、不 busy 重试；短包、超时、未知结果后不补发、不清 stall、不 reset。

型号记录只跳过有界 plist/保留字段/五字节型号代码，要求 `ILCE-7CM2` 与四字节序列号齐全；不解析 plist、不把它解释成固件版本。摘要对四字节序列号的**小写十六进制文本**求 SHA-256，和旧 `getCameraInfo → core.sha(info.serial.encode())` 同源同编码；不能对四字节原值直接求摘要。身份留在内存，不写入日志。

## Mac 接管与释放代码

内部 `_NativeOps` 绑定固定全局锁、受限系统命令、USB 元数据、当前接口描述符及 SDK 管理函数；没有任何工具或 CLI 实例化它。测试替换其系统/SDK边界，未通过管理员权限运行它。

- 全局租约先于枚举、媒体查询和卸载，使用与旧安装器相同的固定锁路径。只接受 root 拥有、单链接、私有权限的普通文件，NOFOLLOW 和非阻塞 flock；释放只关闭，不删除锁文件。未来协调器必须先取得此租约，再创建 Store/取得作业锁，并持有至报告和资源关闭完成；本轮尚未实现这段协调器装配。
- USB 库清点普通和服务 PID，要求唯一预期设备与显式 bus/端口链/address；清点对象释放后重新打开，打开时再次要求唯一且与前一代地址一致。正常→服务→正常之间可变地址，但端口链须一致。IORegistry 独立要求唯一 Sony 普通设备，只取其子树 IOMedia；这还不是 IORegistry 与 USB SDK 同一瞬间绑定的物理证明。
- 磁盘须为已核对的外置 USB、自洽 whole/parent 拓扑；稳定至少 3 秒，总等待至多 20 秒。卸载前后重读完整 registry/拓扑，只正常卸载核实的整盘，不用 force。系统命令输出在读取过程中限制为 8 MiB，超时/超限终止并回收子进程，错误不输出原始内容。
- 明确接口 0、备用设置 0、唯一 bulk IN/OUT；普通 `8/6/0x50`，服务暂要求 vendor class `0xff`，均尚未实机核验。不设置配置、不重置设备；普通驱动仅明确 active=True 时 detach，服务 active 或未知/NotImplemented 则拒绝。
- 所有者在打开返回后、日志 ACK 前收养对象；正常健康关闭依次 release、必要时 attach、dispose。模式切换或未知/日志失败后只显式尝试一次 dispose，不主动重新挂接、补认证或补 stop；借用视图先失效。SDK dispose 可隐式释放接口，SDK 自身终结行为也未验证，因此不是“物理关闭已证”或“零 USB 栈活动”。清理错误不覆盖主错误，也不盲目重试。
- 普通初始和返回各新开一个句柄，各执行一次固定查询，比较同来源摘要与端口链；不消费调用方提供的缓存身份。内部阶段顺序拒绝跳过服务阶段或重放查询。模式切换/stop 本身不在这个模块执行；测试由假系统改变枚举阶段，不能等同于真实认证/退出证据。

独立宿主演练预算为 65,536 个接受的收发字节、共享 120 秒，初始/返回不重置。以后接入完整采集须与材料/认证预算合并，不能拿这个小预算接收完整程序。原始 MSC 读写有明确 timeout；部分 PyUSB 枚举、get_active_configuration、claim/detach/release/dispose 没有该参数，当前只能返回后检查期限，**尚无可中止的真实管理调用总时限保证**。后续还需审阅显式 libusb 后端选择、管理调用阻塞和失败后现场保留。

## 验证与后续边界

新增身份 13 项、宿主 45 项离线测试；完整命令和结果见[第四十九轮](../research/LUT链路调查记录-第四十九轮.md#实际测试命令与结果)。独立报文预期覆盖长度、短响应、状态、源编码与期限；假系统覆盖锁忙、多机/已有服务身份、目标盘变动、接管/释放和日志失败、端口/序列号变化及未知后停止。固定来源只做完整包/成员哈希与 AST 审阅，不执行归档代码。

本轮没有连接[受限认证/材料流](CAPTURE-RAW-OFFLINE.md)、Store、[只读检查器](CAPTURE-INSPECTION.md)和真实采集入口，不产生任何“完整采集”报告；现有三种演练格式保持原样。固件先决字段 2.01 和电量只是内部调用必填条件，测试值全为自制，不能替代实际屏幕读数或完整 AP/CP 指纹。真实协议/新鲜同机材料/恢复/写入/续跑均未验证。

下一步将宿主所有者与同服务句柄认证/材料/stop、全局→作业锁顺序和报告失败语义统一装配，仍先离线。真实管理调用、CSW/端点/响应轮廓和单次服务退出之后另安排受控验证。相机保留原厂 2.00，卡副本不等于内部开发备份；当前无需升级、连接相机、读取移动盘、Docker 或惠普电脑。任何真机采集前另行提示具体范围和所需配合。
