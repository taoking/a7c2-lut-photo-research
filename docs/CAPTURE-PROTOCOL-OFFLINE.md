# N3：固定读取请求与有界协议模型

第四十三轮新增 [captureprotocol](../lutphoto/captureprotocol.py)。它是**被动离线模型**：生成固定请求字节，接收调用方显式提供的自制读取结果；没有 USB、驱动回调、认证、真实 stop 或设备 CLI。不能把它接到现有 Session 就宣称完成采集器。[第四十二轮主机演练](CAPTURE-HOST-OFFLINE.md)仍只使用 SyntheticTape，两者尚未装配为真实设备流程。

编码依据是 QAQLeonard v2.1 `7e54d60b458847f1befa6cfd614fbf004b8b0b90` 的 transport、devicesession/devicejob 与 ma1co Sony-PMCA-RE；保留[署名及许可](../ACKNOWLEDGEMENTS.md)。构造模型时只读取并校验固定 10 成员加载链和 14 成员程序策略，不导入归档 Python、不运行目标代码。没有改变旧安装器、上游锁、哈希、偏移或依赖。

## 固定能力与接收约束

| 项目 | 已实现的离线行为 |
| --- | --- |
| 请求白名单 | ProductInfo HASP；`(0x603,5)` 的 RAM/保存快照；AP/CP 与可选固定 68 UXC 的 Jiritsu 15 选择、17 读取。默认 7 项，包含资源共 143 项；没有任意路径/操作码、16/18、setter 或清理接口 |
| 文件选择 | 读取必须对应本模型先前成功的固定 select；成功读取后消耗选择。选择失败停止后续读取；不自动选择、重试或接受 missing 为成功 |
| 请求编码 | 小端 12 字节 Senser 头及固定命令体；单请求最多 1024 字节，序号从 1 开始，不循环；最多 512 次请求 |
| 服务响应轮廓 | 仅建模 PID 0336 的 12 字节头、最多 1 MiB/段；单次载荷读取最多 32 KiB。头必须完整，载荷可碎片返回；不同 read 的结果不能拼成一条无边界字节流 |
| 额外排空读取 | 按固定 PMCA，在整块长度为 512 倍数时另取最多 512 字节；允许零长度或非零内容，不能传入文件 Sink，不能称其为已验证的零填充 |
| 单响应边界 | 头声明大小、累计分段字节和最大段数在读取该段载荷前检查；AP/CP 用固定原厂精确长度，快照最多 32 MiB，资源最多 1 MiB，HASP 恰好 88 字节 |
| 全程预算 | 同一个 Budget/deadline 贯穿所有请求、碎片和 Sink。段声明先检查剩余载荷额度；另外累计请求、响应头、4 字节状态及排空数据，按最大读取长度预检线路额度；最多 65,536 个读取结果 |
| 主机保存 | 使用既有 Sink，分离 Jiritsu 状态字与文件载荷；完整响应后才 finish/同步及完整读回。测试把自制 CP 载荷保存到真实私人临时目录核对，失败仍保留部分文件 |

`next_read()` 返回本次结果种类、最大长度及剩余总期限的毫秒数。当前没有执行这些读取的驱动，也没有实际 USB 超时保证；未来适配器必须在每个真实阻塞调用前传入剩余期限，不能对每个 read 重置时间。文件系统阻塞也不能被这个模型抢占。`wire_bytes` 计入已接受的请求/读取结果，`Budget.used` 只计文件载荷；被拒绝的超限数据不计作已接受。

## 已知错误、未知结果与退出

- 尚未 begin 的固定名称/Sink 配置拒绝：本地拒绝，没有模拟发送。
- begin 后的发送中断由调用方 abort；短头、错误序号、超限、接收超时/中断、未完成排空或载荷写失败：协议未知，禁止后续读取和退出许可。完成后又收到非请求结果同样转未知。
- 全部响应及必要排空已消费后，非成功 response/Jiritsu status、精确长度不符或主机 finish/fsync 失败：保留已知完整响应，但停止新读取。期限及线路预算仍允许时，最多消费一次本地健康退出许可。
- `claim_exit()` **不发送任何命令**。实际服务退出还必须先持久化意图，并遵守认证状态、同端口及正常身份复核；不能用这个许可绕过日志失败或替代 C5。

完整模型结果的 `simulation_only` 为 true，`physical_protocol_verified`、`response_profile_verified`、`camera_operations_performed` 均 false。88 字节及命令成功不是型号、版本或程序认证；本层不验证完整程序 SHA、BK4、UXC、C0–C5 顺序或捕获新鲜度，这些仍须由后续上层严格完成。

## 必须保留的协议证据缺口

固定 PMCA 只校验响应序号。本模型额外要求 pFunc 回显、version/miconType/offsetType 为零，**这是保守实验限制，尚无 A7C II 真实响应证明**，可能拒绝合法机身响应；不能称已验证协议。也没有把每段 size 必须递减当成协议事实：沿用 `min(size,1MiB)` 和 `size>1MiB` 续段规则，再独立限制声明/累计大小与段数。

PMCA 忽略排空读取的内容/返回长度，因此即使排空结果形似下一段头，本模型也无法凭内容确认其身份。单测明确保留这个限制；需要后续受控传输观测与适配器审阅，不能用自制字节正例消除真实 USB 边界风险。当前仅服务读取模型，第四十四轮的[离线会话协调](CAPTURE-SESSION-OFFLINE.md)补充假认证与临时状态模型，仍没有普通 MSC/真实认证、HASP 身份解析或真实设备句柄生命周期。

## 验证与下一步

离线专项：`.venv/bin/python -B -m unittest research.tests.test_captureprotocol -q`。41 项包含独立黄金请求、分段/碎片/状态、线路/全局载荷/期限、半包/溢出/中断、未知后停止、完整错误的单次许可，以及与私人存储的载荷读回。单测程序策略和响应全为自制，不要求下载归档。另用实际固定归档校验 143 请求/原厂长度，并喂入自制 HASP 和空 AP 拒绝；没有读取真实程序或备份。

第四十四轮已在离线范围装配固定请求、私人存储及会话协调。可选 `guards=True` 仅从固定来源导出 14 个路径，增加 28 个 select/read 操作，原默认 7/143 请求保持不变；只有守卫完整 missing 状态字可表示模拟不存在，存在包括空文件均停止，详见[会话说明](CAPTURE-SESSION-OFFLINE.md)。没有 USB、真实系统锁或设备 CLI。第四十五轮已有[旧目录只读检查与中断分类](CAPTURE-INSPECTION.md)，第四十六轮另有独立[原始认证离线适配](CAPTURE-AUTH-OFFLINE.md)，尚未与材料流装配。下一步在自制流程中统一认证、预算和一次退出，协议真实边界另行审阅。当前无需相机、Docker 或惠普电脑。见[总计划](../plan.md)、[交接](../research/HANDOFF.md)及[本轮记录](../research/LUT链路调查记录-第四十三轮.md)。
