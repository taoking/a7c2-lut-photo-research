## 所有权核对与修正

每次枚举生成新的假SDK对象。用于库存观察的对象仅被枚举/释放，不做配置、认证或材料收发。原生open方法重新枚举并选择唯一对象；该对象先归Host所有者，再读取当前配置，模拟SDK在此处惰性打开。OPEN确认日志失败时，即使对象尚未惰性打开，也只尝试一次本地释放。

初始普通、服务和返回普通使用三个不同对象。只有服务所有者处理服务认证/材料/stop，返回普通身份重新查询。转场或未知状态不显式重挂；假SDK的dispose可以模拟隐式释放接口，记录与显式release分开。它不是物理释放或服务退出证明。

组合测试先复现并修复两个问题：

- 异常枚举可能重复引用同一SDK对象，旧清理逐项调用造成重复释放。现在仅清理按对象身份去重；重复库存观察仍保留并拒绝，不把它们折叠为“唯一相机”。枚举中途失败仍清理已收纳对象，不反复调用失败的dispose。
- 取得全局锁失败后，关闭fd也失败会覆盖原错误。现在主异常继续向外抛出，关闭异常通过异常链保留，仍只尝试一次关闭；不把它解释为已确认释放，不创建作业、不继续设备动作或重试锁。

配置/claim/释放、日志失败和原始收发未知均继续遵守既有停止规则。完整报告必须满足既有owned证据，所有实际设备/恢复/写入标志仍false，不增加第五种报告或可运行的设备命令。
