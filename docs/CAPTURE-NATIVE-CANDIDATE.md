# 原生协调候选与首次采集清单

第五十二轮交付[协调候选](../lutphoto/capturecandidate.py)，在精确自制系统上复用[统一装配](CAPTURE-OWNED-OFFLINE.md)的所有权、认证、材料、等待、取消及日志逻辑。**本候选模块的capture仍无条件拒绝，CLI只作源码review。** 第五十七轮另交付独立[首次采集入口](CAPTURE-FIRST-USE.md)，未改变候选review的含义；新入口也仅离线验证。本页冻结的是待审阅范围，不是设备操作授权或已完成的实测。

## 候选与既有演练的区别

| 项目 | 候选行为与证据 | 剩余缺口 |
| --- | --- | --- |
| 操作接口 | 假系统只暴露 NativeOps 使用的 18 项有限能力，管理/收发签名对齐；不提供任意后端、驱动或回调参数 | 未用真实 SDK/系统命令运行候选 |
| 设备到达 | 协调器不调用模拟到达接口；假世界在枚举时安排到达，协调器只做有界被动等待 | 假枚举不是相机重枚举证据 |
| 句柄与材料 | 初始普通、服务、返回普通共三所有者；同服务对象完成认证/材料/stop，返回身份重新 MSC 查询 | 实际端点、CSW、应答回显/排空与机身绑定未证 |
| 关闭与发布 | 共用全局租约→新作业锁，先关闭句柄，再发布报告、关闭作业、释放租约 | 真实系统锁、阻塞管理、释放后的设备状态未验 |
| 现存证据检查 | owned 格式增加严格的候选标记，必须标明 live=false；完整候选必须有两段等待且不能含模拟到达动作 | 哈希链只说明一致性，不是签名或执行许可 |

公共演练只接收精确、全新的 SyntheticSystem；协调过程中不保留假 peer/到达接口。第五十五轮进一步拆出共用所有权核心，候选构造和内部执行生命周期不再接收模拟系统；旧到达动作只在旧演练适配中。真实 capture 函数在读取参数/文件之前无条件拒绝，没有启用开关。命令行只有下面的源码审阅，没有 capture、安装或版本覆盖选项。

## 可执行的源码审阅

```sh
.venv/bin/python -S -B -m lutphoto.capturecandidate review \
  --archive research/materials/upstream-v2.1-audit/a7c2-tools-2.1.zip
```

可加 `--resources` 查看明确选择的 68 个资源扩展。不加 sudo、不连接相机；不需要 Docker、Windows 或 AArch64 Linux 共享库。命令只读固定包，核对来源与原厂策略，输出有限 JSON；不导入 SDK、不申请锁、不建目录或报告文件。退出 0 只表示源码审阅完成，阶段仍为 `NATIVE_CANDIDATE_BLOCKED`，全部设备验证/恢复/写入标志均 false。

输出列出需求、6/74 个落盘材料、14 个守卫名、35/171 种固定逻辑请求的长度/摘要/上限和阶段顺序，不输出请求原文、认证密钥、机身身份或个人路径。种类数不是实际调用次数；程序、资源、设置和守卫的重复读取仍由既有材料流程约束。修改 JSON 或声称 live=true 不能开启采集。电脑端输出位置和环境检查仍用[只读预检](CAPTURE-CONTROL-PREFLIGHT.md#只读预检命令)，两份 stdout 都不是可导入的采集材料。

## 首次采集的冻结清单

下表尚未在本项目真实采集路径执行。进入设备阶段前会提示用户，并取得实际信息和连接配合；不以本轮“继续开发”替代安装或设备采集请求。

| 阶段 | 必须满足/保存的事实 | 不满足时 |
| --- | --- | --- |
| 进入前 | 用户明确选择首次采集；本人 ILCE-7CM2 原厂 2.01、实际电量至少50%、物理连接/取电条件和管理员认证；固定来源、依赖、全新私人输出位置和空间 | 不启动设备流程；不猜版本、电量、端口或权限 |
| 宿主占有 | 同一固定全局锁后取得新作业锁；唯一普通机、同端口、稳定磁盘和普通卸载，当前接口/端点匹配 | 不强制卸载/复位；不覆盖已有目录或混用其他机身备份 |
| 普通到服务 | 当前普通句柄完成新 MSC 型号/来源身份查询和固定认证，关闭后被动等待唯一同端口服务设备 | 未确认动作保留 INTENT，停止；不重发认证 |
| 读取前守卫 | 固定认证后读取 hasp，确认13个临时名字及 preload 均不存在；守卫内容不落盘 | 存在、读取不明或不匹配均停止，不删文件/清状态 |
| 原厂程序 | 完整读取 AP、CP，并且各自长度及完整 SHA-256 同时匹配固定原厂策略 | 不读取设置或资源；只在协议健康、已知且未取消时允许一次固定退出 |
| 核心材料 | 保存 `source/appFw.so`、`source/cpapp-b.bin`、初始 RAM/saved 设置和结束 RAM/saved 设置，共6个；保存格式/作用域检查证据 | 不把快照容器、芯片角色或新鲜度视为已经证明 |
| 可选资源 | 仅显式选择时读取固定68个 UXC，合计74个材料；程序/资源再读取校验，设置按作用域比较，结束再查守卫 | 任意缺失/变化均不宣告完整；不扩大任意路径范围 |
| 健康退出 | 同服务句柄一次明确 stop，关闭；被动等待普通返回，新开第三句柄重新 MSC 查询并匹配原来源 | 不凭同PID或缓存身份补成功；未知不重试 stop |
| 发布 | 三句柄关闭确认、材料落盘回读/摘要及日志完整，再发布私人报告；作业关闭后释放全局锁 | 关闭失败不能以已有报告掩盖；不覆盖主错误 |

服务认证和选择读取文件会改变临时会话状态，因此未来采集不是“完全无设备操作”。本范围不上传/删除文件、不加载或执行临时机内模块、不写程序、不保存设置、不做 WBI。原厂完整程序不匹配时不放宽校验适配 FL2/FL3、Custom LUT 或修改升级包；这些迁移/恢复属于独立任务。

## SDK 阻塞、取消与现场保留

管理调用没有可保证的硬超时，详见[控制边界](CAPTURE-CONTROL-PREFLIGHT.md#合作式取消与原生阻塞审阅)。合作式 token 只在调用前后和轮询间检查；第五十四轮已验证[显式信号作用域](CAPTURE-SIGNALS-OFFLINE.md)，但没有接入实际设备 CLI 或承诺 Ctrl-C 可安全收尾。实际 CLI 在现场处理方式经审阅前继续关闭。

- SDK 调用尚未返回时，协调器不能凭期限推断成功、失败或释放；当前所有者、作业及锁仍由该流程持有。不要并行启动另一个相机工具、强杀、复位或盲目重试；不把锁文件存在等同于仍持锁，进程被杀时系统锁也可能消失。
- 调用返回后才可检查取消/超时；OPEN 返回对象先接收所有权，再检查取消。未知结果停止新增协议动作，仅按既有逻辑单次尝试本地 dispose；这也可能阻塞，不等于 stop 或物理释放确认。
- 日志失败也尝试关闭本地对象，保留原错误和次要关闭错误。不补 ACK、不重挂未知驱动、不把等待耗尽当退出成功；静态检查器可以仍判未知。
- 保留当前私人工作目录及进程/连接现场，后续由人工结合已确认动作决定处理；本页不授权拔线、取电池、重启或恢复写入。卡副本和两份备份都不能保证救回不能启动的机身。
