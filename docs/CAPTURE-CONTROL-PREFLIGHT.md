# 重枚举等待、取消和只读预检

第五十一轮完善[统一离线流程](CAPTURE-OWNED-OFFLINE.md)，新增有界重枚举、合作式取消和电脑端预检。**设备采集入口仍关闭。** 只有新预检命令可直接运行，它不枚举 USB、不加载 SDK、不申请系统/作业锁、不创建工作目录、不安装依赖或改变权限。本轮不操作相机、移动盘或原生模块。

## 有界重枚举与结果边界

完成初始认证/关闭后等待服务设备，明确 stop/服务关闭后等待普通设备。每段最多 20 秒、40 次观察，使用同一 1200 秒总期限；约每 0.5 秒观察一次。只允许等待空结果或同物理端口尚未消失的旧 PID；预期设备必须连续两次具有相同 bus/端口链/address 且间隔至少 0.5 秒，之后才打开。打开时仍重新要求唯一匹配，打开失败不重试认证或重新接管。

多机/新旧 PID 同时出现、不同端口、异常枚举结果/权限错误立即拒绝；不把它们当成普通等待。观察超过局部期限后即使 SDK 终于返回预期设备也不能按准时到达处理；全程期限在 SDK 内耗尽时保留未确认动作。真实设备到达/端点/协议兼容仍未实测，假系统时间和脚本不构成物理证明。

| 结果 | 保留的事实 | 禁止推论 |
| --- | --- | --- |
| `ObservationTimeout` | 本宿主已记录等待结束；先前明确的认证或 stop 结果仍保留。单纯没有观察到设备不把此前协议结果改成未知 | 不能证明相机已返回、退出成功、可重试或可重启 |
| SDK/控制/传输超时或异常 | 完整结果无法确认，仍保留未知；SDK 抛出的同名异常也不能冒充本宿主等待结束 | 不补认证/stop、不 clear/reset/强制卸载 |
| `OperationCancelled` | 在合作式检查点观察到取消；已接收对象仍只显式尝试一次本地 dispose | 不能中断正在阻塞的 SDK 管理函数，也不保证物理释放 |

报告仍为第四种 owned 格式，没有添加真实完成许可。日志新增 `HOST_WAIT_BEGIN_MODELED` / `HOST_WAIT_END_MODELED`，仅记录阶段、结果、轮询次数，不记录设备地址或身份。检查器核对它们与实际库存确认记录、外层阶段位置一致；旧的不含等待标记的 owned 目录继续支持。

**只读检查仍保留未确认的普通/服务观察 INTENT。** 即使报告说明“stop 已确认、只是等待超时”，检查器也不会凭等待标记伪造观察 ACK，分类仍可为 `NEEDS_REVIEW_UNKNOWN`。这是现存证据不完整，不等同于丢失原进程已经取得的 stop 结果；也不授权续跑。

## 合作式取消与原生阻塞审阅

新增精确 Cancellation token，无调用方回调、原因文本、信号处理、线程/进程终止或自动重跑。开始前、宿主调用/原始收发前后及轮询之间检查；取消后停止新协议动作，未知状态不主动重新挂接驱动。打开返回值先归所有者接收，再检查取消，因此此处取消仍可单次释放。日志失败也不跳过本地释放，仍不能将其写成相机协议退出。

只读核对本机 PyUSB 1.3.1 的 core/util/libusb1 后端源码，未导入 SDK 或加载本地库：

| 调用 | 当前接口事实 | 限制 |
| --- | --- | --- |
| 枚举、open/close、当前配置、claim/release、detach/attach | 后端方法无 timeout 参数 | 调用前后可查取消/期限，无法抢占正在阻塞的调用 |
| bulk read/write、control transfer | 后端传输带 timeout | PyUSB 包装在传输前还可能执行配置查找/接口声明，所以整个 Python 调用仍不保证硬时限 |
| ioreg/diskutil 子进程 | 独立输出/时间上限及回收 | 不代表 SDK 调用也可中止；本轮仍只以假进程验证 |

不通过直接杀死持有未知相机状态的进程或重试来假装解决硬超时。预检明确返回 `native_management_interruptible:false`、`live_capture_enabled:false`；实际信号/SDK 阻塞/关闭后的现场保留尚需原生候选审阅和受控验证。

## 只读预检命令

在已有研究环境/固定源码包下，给出仓库外的**新输出目录名**，其父目录须已存在、本人拥有且不共享可写。例如使用现有“图片”文件夹作为父目录：

```sh
.venv/bin/python -B -m lutphoto.capturepreflight \
  --archive research/materials/upstream-v2.1-audit/a7c2-tools-2.1.zip \
  --directory "$HOME/Pictures/A7C2-capture-new"
```

**不加 sudo、不连接相机。** 命令只读固定归档、依赖分发元数据、指定父目录权限/当前空间和目标名字是否已存在；不创建上面路径，不读取照片或已有备份。已有目录、文件、链接或不可信父链拒绝，不删除/覆盖；`--resources` 仅增加可选 68 资源的空间估计，不读取资源。

来源、macOS/Python 和两项固定原生依赖、当前可用空间满足时返回 `OFFLINE_PREFLIGHT_CHECKED`、退出 0；本地条件不足为 `OFFLINE_PREFLIGHT_INCOMPLETE`、退出 1；不安全路径/来源失败为 `REFUSED`、退出 1。参数错误为标准退出 2。正常检查不要求当前为管理员，权限只做电脑端事实记录；不会索取密码。

输出仅有限私人 JSON，不写报告文件/个人绝对路径或原始错误。空间没有被保留，检查后仍可能变化；不检查真实全局相机锁、USB 权限、电量、版本、机身身份、完整原厂程序指纹或恢复条件。这些验证标志均为 false，并列出缺失设备证据；`OFFLINE_PREFLIGHT_CHECKED` 不是“相机已就绪”。不要将 stdout 当采集目录送给旧目录检查器，也不要据此运行 prepare/diagnose。
