# 宿主、身份、认证与材料流的统一离线装配

第五十轮新增 `lutphoto.captureowned`，将[Mac 宿主/MSC 查询](CAPTURE-MAC-OFFLINE.md)、[受限认证/材料收发](CAPTURE-RAW-OFFLINE.md)、私人 Store 和[只读检查](CAPTURE-INSPECTION.md)连接起来。**公共入口只接受精确、未使用的 SyntheticSystem，仍没有真实采集 CLI。** 不接受 NativeOps、外部 Session、子类、回调、策略覆盖或旧目录续跑；不导入 USB/原生共享库。本轮没有设备操作、系统锁、管理员命令或移动盘读取。

来源沿用 QAQLeonard 固定 v2.1、ma1co MSC/Sony 协议与 ajalt 哈希设计，11/9/10/14 成员及旧固定清单均保留。[致谢](../ACKNOWLEDGEMENTS.md)和完整许可不变；不发布密钥、原始应答、身份、固件或备份。源码/完整包校验发生在任何模拟宿主动作之前，旧安装器/默认单份备份不改。

## 三个所有者，共享一段服务通信

| 顺序 | 句柄与动作 | 持久证据 |
| --- | --- | --- |
| 1 | 模拟全局租约，然后创建新私人 Store/取得真实作业 flock | Store 创建前全局租约已在模型中持有；系统相机锁仍 false |
| 2 | 核对普通设备/媒体、正常卸载、接管；显式 MSC 查询，再普通认证 | 外层 normal-before 与宿主查询各有 INTENT/ACK；身份来自自制原始响应 |
| 3 | 初始普通所有者失效并单次 dispose；模拟服务到达，重新打开服务句柄 | 独立关闭记录，位于普通认证之后、服务观察之前 |
| 4 | 服务认证、固定 hasp/守卫/程序/快照、可选 68 资源、复读、结束守卫 | 认证、材料和 stop 借用**同一个**服务所有者及唯一端点；不是两套独立传输 |
| 5 | 明确一次 stop 返回，再失效并 dispose 服务所有者 | stop 证据和 SDK dispose 证据分别保留；后者不证明相机退出 |
| 6 | 模拟普通到达，打开第三个句柄，重新 MSC 查询并比较同来源身份/端口链 | 不使用 SyntheticPeer 的缓存身份；返回查询须发生在 stop 与服务关闭之后 |
| 7 | 健康普通接口 release/必要 attach/dispose，验证全部证据并发布报告 | 三角色关闭均明确，报告仍在模型全局租约与真实作业锁内写入；再关 Store，最后释放模型租约 |

本页“模拟到达”只是改变假系统的枚举结果，不代表真实认证会造成这些状态变化。所有端点、2.01/电量、bus/端口和身份材料都是自制输入，不能替代用户相机读数、完整原厂 AP/CP 指纹或真实端口证据。

只有 `_Owner` 管理 SDK 资源；认证和材料视图借用它，没有析构关闭权，也不能独立关闭。打开结果在日志 ACK 前已被接收，ACK 失败仍尝试释放。关闭先使所有视图失效，每个已接收对象只显式尝试一次 dispose；日志已损坏也不跳过本地释放。未知/切换后不主动重挂驱动、不补认证或 stop。SDK dispose 可能隐式释放接口，SDK 终结行为也未验证；一次显式调用不是物理释放证明。

完整响应后的内容拒绝仍可尝试一次已有健康退出；半包、未知控制/读写、日志失败或释放不明均停止额外协议命令。主错误和清理错误类型分别保留，不记录异常原文；不重建目录、不补确认或重跑。Store 关闭/模型解锁失败会抛出错误，**即使完整报告文件已经存在，也不能据此声称整个调用成功**。

## 预算与第四种证据格式

身份/认证/材料共用一个在宿主动作之前建立的 1200 秒 Budget。额度由固定材料最大载荷、32 KiB 认证余量和 64 KiB 身份余量组成；新阶段不重置。身份计数包含 MSC CBW、CSW、请求与响应，认证计数仍为 14,448 字节/31 次视图调用，材料载荷/材料线路含义保留，不重复计费。两次完整身份查询为 28 次原始调用；主机管理动作不计为数据字节。

新报告 `owned-report.private.json`，schema `a7c2-synthetic-owned-capture/1`；完整 phase 仅 `SIMULATED_OWNED_CAPTURE_COMPLETE`。增加身份接受字节/查询/调用数、已打开/明确关闭的所有者数、模型宿主绑定和有限错误类型，不写原始身份或主机路径。真实源、认证、协议、普通观察新鲜度、系统锁、恢复、写入和续跑标志继续 false。

只读检查器仍使用已有 inspect 命令，新增识别第四种格式；不需要源码包。核对宿主 INTENT/ACK、三个唯一角色关闭、宿主顺序、查询/打开/释放在材料确认序列中的位置，以及三类计数加总。重复动作名的未确认记录单独保留，后续同名 ACK 不消除旧未知。原三种格式不获得宿主证明，也不能混入新宿主记录后继续声称完整。

哈希链不是签名，检查结果只判断现有模型证据是否一致，不证明实际执行、真实机身或解锁成功；完整正例依旧只在自动测试中用 tiny 自制程序策略。实际固定原厂策略演练使用全尺寸全零 AP，必须拒绝。

## 验证与仍未完成的部分

新统一专项 37 项，宿主补充 4 项；研究 707、原 Mac 39、旧上游 8，合计 754 项通过。完整命令见[第五十轮](../research/LUT链路调查记录-第五十轮.md#实际测试命令与结果)。固定包/真实密钥只在内存校验，SHA-256 包预期由独立标准库计算；六种自制材料场景再经过真实 -S 只读检查 CLI，输入内容/inode/权限/写时间不变，临时目录清理。没有执行归档 Python 或目标代码。

内部原生绑定已明确选择并缓存现有 libusb-package 的解析器/后端，向每次枚举显式传入后端；仅用假模块测试成功/缺失路径，未加载实际库。部分 SDK 管理调用没有 timeout，当前仍只能返回后查期限，**不能保证抢占正在阻塞的枚举/配置/接口管理**。不为达到硬超时直接杀死持有未知设备状态的流程或自动重试；真实入口继续关闭。

下一步聚焦原生管理调用的阻塞/中断边界、退出后延迟重枚举和入口前只读预检，再确定受控真机采集条件。真实 MSC/CSW/端点/回显/排空、原厂材料与新鲜同机来源尚缺；事务/worker/恢复、独立介质和 N4 色彩验证另验。相机继续保留原厂 Ver.2.00，卡副本不等于内部开发备份；目前无需升级或连接相机、Docker、惠普电脑，进入真机操作前另行提示。

第五十一轮新增[有界重枚举、合作式取消及只读预检](CAPTURE-CONTROL-PREFLIGHT.md)。等待超时保留已知 stop，但不伪造设备观察 ACK；采集 CLI 仍关闭，SDK 管理阻塞不能抢占，旧入口/报告继续兼容。

第五十二轮将固定来源准备与 Store/全局租约执行封装为内部共用逻辑，原公共演练仍只接收精确假系统。新增[协调候选](CAPTURE-NATIVE-CANDIDATE.md)通过 NativeOps 形状的有限假能力，被动等待枚举、不使用模拟到达钩子，其他认证/材料/所有权逻辑共用；没有新增实际设备入口或允许任意后端的公共参数。
