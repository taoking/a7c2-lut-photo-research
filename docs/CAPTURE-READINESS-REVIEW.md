## 必须区分材料报告和调用终态

本轮复现了两个具体反例：核心材料和返回身份均完成、三个设备对象已关闭，报告已经落盘；之后作业关闭报错，或全局租约释放报错。调用抛出 OSError，已有检查器仍会把目录判作 `CONSISTENT_SIMULATION_COMPLETE`。该分类检查的是现有模拟证据，不能作为整个进程成功的凭据。

真实集成应同时满足下列约束，具体 schema/CLI 在实现时与测试一并提交；本页没有提供尚不存在的运行命令。

1. 材料证据在作业锁和全局租约内写入，明确其观察截止点。作业/租约结束和处理器还原未确认时，不在该报告声称全流程成功；不在锁外重开目录、覆盖旧报告来补成功。
2. 调用终态在本地对象关闭、Store 关闭、全局租约释放、信号还原全部尝试完成后产生。保留首个失败以及有限的次要收尾错误类型；不输出异常原文、身份、密钥或私人路径。
3. 只有请求材料/复读/守卫/正常返回身份均满足、所有关闭与还原确认、最终检查未观察到取消，才允许成功退出。已知内容拒绝、协议未知、主机存储失败、清理失败、还原失败和取消均为非成功；不能以已有完整文件覆盖它们。
4. 参数/来源/电脑前置拒绝发生在任何 SDK/租约/作业动作前；设备动作开始后的失败另作区分。源码 `review` 的退出 0 仍仅表示审阅完成，不复用为实际采集成功。
5. SDK 阻塞期间仍保留当前对象、作业和租约，不通过子进程强杀、线程取消、复位或超时解锁实现退出。返回后才处理合作式取消；未知不新增协议命令、不补 ACK、不重发 stop。
6. 离线检查应分别报告材料证据与终态证据是否可验证。只有材料报告、stdout 丢失、收尾未确认或进程被杀时，不能推断整体成功、设备已恢复或允许续跑。

跨系统调用、日志和进程退出不能构成原子事务；即使增加终态输出，也不能保证进程突然死亡后留下完整回执。未知应保持未知，不把备份/哈希链描述为恢复保证。
