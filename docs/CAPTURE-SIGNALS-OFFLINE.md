## 安装与处理范围

SignalCancellation仅接收精确Cancellation，由调用者在主线程、取得任何采集租约/作业之前显式进入。导入模块和构造对象不安装处理器；已有演练/源码审阅/预检入口也不会自动启用它。

只允许SIGINT为默认中断处理器或SIG_DFL、SIGTERM为SIG_DFL。已有自定义、忽略、未知处理器，工作线程、嵌套、重用或已取消token均拒绝；不调用旧处理器，不提供任意回调、信号选择、链式转发或升级为强制退出的开关。每次安装后读回确认，安装期间收到取消会还原并拒绝进入正文。两项处理器安装不是原子操作，进入前及退出后的信号仍受原有进程规则控制，不应把它套在已开始的设备动作外面。

Python信号处理函数只赋值一个布尔标志，不调用Event.set/cancel、同步原语、日志、磁盘、SDK、资源释放、异常或进程终止。普通跨线程取消仍使用原Event；两种请求都由既有检查点观察。重复信号仅重复记录请求，不自动强杀或重试。帧/身份/路径不会保存在作用域中。

## 模拟调用未返回时保留什么

| 时机 | 当前行为 | 不能推断 |
| --- | --- | --- |
| 模拟配置查询内 | 已选对象先归Host所有者；请求取消后仍保留所有者、全局假租约及实际私人作业锁 | 不能认为SDK已经返回、可安全重试或释放完成 |
| 模拟材料发送/stop内 | 已发出的动作不回滚；取消本身不追加读取/stop/重枚举，返回后由原检查点停止 | 不能补成功ACK或声称服务退出 |
| 模拟dispose内 | 借用视图已提前失效，仍保留所有者记录、作业与租约，返回后不重复dispose | 视图失效不等于SDK/设备物理释放 |
| 作用域结束 | 只还原仍属于本作用域的处理器，并读回核对；取消标志保留 | 还原进程处理器不是相机恢复或续跑许可 |

实际CPython处理信号的时机受底层调用影响。真SDK长时间不返回时，Python处理器也可能迟迟不运行；即使请求已记录，也无法抢占SDK。某些底层调用可能自行返回异常，仍按未知结果停止。这里没有引入C调用硬时限、后台设备重试、SIGKILL/SIGSTOP处理、进程强杀或USB复位。

## 失败与还原

安装失败会逆序核对并尝试还原已归本作用域的处理器；同时考虑调用抛错前后是否已改变处理器。安装期间发现状态变化时停止，保留实际返回的前任处理器，不调用它。还原遇到外部新处理器时不覆盖，仍尝试还原其余自有处理器。

还原失败或读回不符抛SignalScopeError，`restoration_confirmed`保持false，不反复重试。正文/安装已有异常时保留主异常，并通过异常链保留还原失败；没有主异常时，还原失败也不能按成功返回。错误不包含原始路径/身份。这个诊断字段不是执行授权，修改它不能开启真实采集。

## 实际离线验证

无需sudo、相机、Docker、Windows或AArch64共享库，使用现有项目环境：

```sh
.venv/bin/python -B -m unittest discover -s research/tests -p 'test_capturesignals.py' -v
```

24项通过：20项作用域/失败/导入检查和4项真实子进程信号测试。真实信号仅发送给测试刚创建的自制子进程：配置查询SIGINT、材料发送SIGTERM、stop控制SIGTERM、dispose期间SIGINT。子进程以第五十三轮假SDK驱动现有NativeOps/候选/Store；父进程先确认取消已被观察、调用仍未返回、作业仍ACTIVE_JOB、协议计数未增加，才允许假调用返回。

四种场景最终均OperationCancelled/NEEDS_REVIEW，检查器NEEDS_REVIEW_UNKNOWN；stop ACK/返回身份均不伪造，SDK对象仅一次释放尝试，实际设备标志false，处理器读回还原。测试故障清理可终止其自制子进程以防测试遗留，此能力只在研究测试代码，不属于采集实现或设备超时方案。

既有控制/原生组合40项回归通过；研究804、旧Mac39、旧上游8，合计851项。另完成86条AST观察/51来源身份、固定来源八场景及实际只读CLI检查；八场景进入显式信号作用域但不发信号，正常还原。详见[第五十四轮](../research/LUT链路调查记录-第五十四轮.md#实际测试命令与结果)。
