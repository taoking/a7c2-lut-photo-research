# N3：会话协调与固定读取的离线装配

第四十四轮新增 [capturesession](../lutphoto/capturesession.py)，将[被动协议模型](CAPTURE-PROTOCOL-OFFLINE.md)、[私人存储](CAPTURE-HOST-OFFLINE.md)及材料验证装配为自制演练。**没有 USB、真实认证、真实系统相机锁或设备 CLI。** 入口 `rehearse` 只接受精确的 SyntheticPeer 类型；不支持传入 Session、驱动、锁回调或程序策略覆盖。上一轮 SyntheticTape 入口保持原样。

来源仍为 QAQLeonard v2.1 `7e54d60b458847f1befa6cfd614fbf004b8b0b90`、ma1co Sony-PMCA-RE 及继承的 Mac 生命周期设计，保留[署名和许可](../ACKNOWLEDGEMENTS.md)。实际固定归档只读核验 10/14 成员与 N1 的 26/旧 46 成员，不执行归档 Python，不改变旧安装器、锁、程序指纹、偏移、测试或依赖。

## 装配后的演练流程

| 阶段 | 本轮实现 |
| --- | --- |
| 主机与互斥 | 模拟取得旧系统锁，再创建仓库外新私人目录、取得真实作业 flock；空间预检先于假设备查询，报告发布及句柄释放后才释放锁。系统锁路径只是常量，从未打开 |
| 普通身份 | 严格要求一台普通 Sony/ILCE-7CM2、无既有服务身份，协议序列摘要明确来自 `sony-get-camera-info`；总线及物理端口必须有效。拒绝忙碌、缺身份或不同身份来源，不走服务模式补认分支 |
| 两段认证 | 假普通认证 start/verify、同端口唯一服务身份、假服务认证 start/verify；每步意图先落盘，再执行假动作，返回后记录 ACK。未知结果不重试，不补发 stop |
| 既有临时状态 | HASP 模型之后、完整程序之前，以及结束复读之后，各检查 14 个固定路径；13 个来自固定 core.NATIVE_PATHS 与 devicesession.TEMP_NAMES 的并集，另有 `/etc/ld.so.preload` |
| 原厂程序门槛 | 固定 AP 完整保存/核对后才读 CP，两份均匹配固定原厂完整长度与 SHA 才读快照/资源；已知 FL23 也不作为首版采集源放行 |
| 材料与复读 | 初始 RAM/保存 BK4、可选 68 UXC；程序/资源完整复读、结束快照指定范围比较。RAM 与保存值可以不同，BK4 芯片角色和容器完整性仍未判定 |
| 健康退出 | 持久化 stop 意图后才消费一次本地许可及假 stop；已知 ACK 在写日志前更新内存，避免日志失败引起重复退出。正常返回后重新核对同一种协议身份、型号、唯一性及完整物理位置 |

普通 USB 描述符序列和协议序列摘要不混用。假返回观测不能只凭 PID 通过，也不能把 HASP 的 88 字节当作型号认证。SyntheticPeer 的默认版本/电量/身份均为明确的自制输入，没有读取或确认用户相机信息；将来设备入口仍须取得用户实际菜单版本、电量及授权。

每个固定 select、read、快照、HASP，以及假认证/普通查询均分别记录 INTENT/ACK。完整资源流程会超过旧演练的 512 个事件，因此 Store 新增显式 `events_limit`，默认仍为 512、最多 2048；本协调器使用 2048，每项仍最多 16 KiB，并纳入空间预检。文件排他、私有权限、同步读回、有限载荷/线路/期限、失败保留规则不变。

## 临时状态与错误处理

守卫只有两种可继续/停止的已知结果：**只有固定守卫 read 的完整 `0x10000006` 状态字且没有额外载荷，才记为模拟不存在**；状态 0 表示存在，哪怕文件为空也停止。其他状态或缺字节拒绝。普通程序/资源读取不接受 missing。

每个守卫最多接收 4096 字节载荷，使用 hash Sink，不保存临时文件内容、不修改或清理它们。超限时协议未知，停止后续命令；已完整收到的存在结果则停止新读取，允许一次有日志的健康退出。守卫只证明这次自制观察，不能排除相机在两次观察间发生变化，也不证明加载器状态、目录项类型或所有临时文件都已列全。

发送前日志失败不执行相应请求；接收半包/中断/写满视为未知，之后只释放本地主机资源。完整响应后的程序/格式/复读/同步拒绝可单次退出，但必须还能持久化退出意图。退出未知、退出 ACK 日志失败、普通身份变化均不能完成；不套用旧流程的 usb_unconfirmed 特例。失败日志或报告可能不完整，不能只看文件中的完成字段，更不能自动覆盖/重跑；第四十五轮已有[旧演练目录只读检查](CAPTURE-INSPECTION.md)，不补写确认或提供续跑许可。

## 真实适配前的新缺口

固定 PMCA 的 `SonySenserAuthDevice.start/stop` 会捕获 `GenericUsbException` 后直接返回。因此**方法没有抛错不等于取得明确成功证据**。本轮假动作要求显式 True，并未调用或包装这两个真实方法；不能把现有方法的 None 返回强转为成功。第四十六轮另有独立[原始认证离线适配](CAPTURE-AUTH-OFFLINE.md)，要求控制/发送明确长度、完整响应及共享剩余期限，在精确假驱动上实现两段认证和一次退出。第四十七轮另有[统一离线协调器](CAPTURE-PIPELINE-OFFLINE.md)复用本材料方法接入原始认证，本节旧入口的两段认证仍是假动作；真实 USB 兼容和正常身份新鲜查询未证，保留旧安装器原行为。

本页记录第44轮的离线入口；pFunc回显/零字段仍为未获机身证据的保守限制。第74轮已取消材料流的主动排空，空传输与有效续块按[当前读包规则](CAPTURE-PROTOCOL-OFFLINE.md)处理。真实接口/认证/完整材料闭环仍未通过，后续原生入口与失败状态以[当前交接](../research/HANDOFF.md)为准。

模型报告仅为 `SIMULATED_SESSION_COMPLETE` 或 `NEEDS_REVIEW`，真实设备、系统相机锁、程序来源/机身绑定、芯片角色、外层容器、快照新鲜度/原子性、独立介质、原生执行、恢复和写入许可标志仍 false。只有自制 tiny 策略正例；实际固定归档练习生成全尺寸全零 AP 并预期拒绝，不构成真实材料成功证据。
