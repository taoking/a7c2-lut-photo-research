# N3：原始认证与固定材料流的离线装配

第四十七轮新增 [capturepipeline](../lutphoto/capturepipeline.py)：同一协调器按顺序执行[原始认证模型](CAPTURE-AUTH-OFFLINE.md)、既有[固定材料流程](CAPTURE-SESSION-OFFLINE.md)及一次退出，再由[只读检查器](CAPTURE-INSPECTION.md)核对新格式。**没有真实 USB、系统相机锁、设备句柄或采集 CLI。** 公共入口只接受全新且精确的 SyntheticPeer、普通/服务 SyntheticDriver；不接受真实 Session、子类、调用方回调、策略覆盖或已有目录续跑。

材料响应仍由 SyntheticPeer 提供自制帧，认证由两个独立假驱动提供脚本结果；没有证明二者共用真实接口、端点或机身句柄。第四十八轮另有[受限原始接口入口](CAPTURE-RAW-OFFLINE.md)，让认证/材料共用同一模拟服务对象，本页旧入口保留。型号、版本、电量、端口和正常身份均是明确的自制输入，不能代替用户相机信息。用户保留原厂 2.00 不影响本轮离线开发，也不改变真实采集设计只支持精确原厂 2.01 的门槛。

## 顺序与复用

保留旧 SyntheticTape、SyntheticPeer 和独立认证入口。将原会话的空间/日志预检与固定材料部分提取为共用内部方法；新协调器复用程序原厂指纹、HASP 模型、14 个首末临时守卫、快照格式/范围比较、可选 68 资源和完整复读，不复制一套较宽的策略。

| 阶段 | 新流程 |
| --- | --- |
| 预检与普通观察 | 模型全局锁先于真实私人作业锁；空间预检先于假身份查询。型号/身份来源/总线/端口须明确 |
| 普通认证 | 固定原始 start 和三轮认证；每个 start/整段认证先 INTENT 后动作再 ACK，不再调用旧 True 假认证 |
| 服务转换/认证 | 同端口唯一服务观察；固定原始服务 start/三轮认证，完成后记一条 RAW_AUTHENTICATION_MODELED，包含 14,448 认证字节及 30 次假调用 |
| 固定材料 | 两份完整原厂程序分别保存并验证后才读快照/资源；结束完整复读、范围比较和第二组守卫。程序拒绝不修改或覆盖原件 |
| 一次退出 | 共享协议层只消费本地退出许可；实际假 stop 由认证层发送一次。退出意图落盘后才发送，正常查询也在其 INTENT 落盘后才发生 |
| 发布 | 同来源普通身份匹配、模型句柄关闭、文件/日志复核后发布新私人报告；作业锁/模型全局锁最后释放 |

正常返回查询采用内部绑定的精确假 peer，不对公共入口开放查询回调。已明确返回的 stop 与身份匹配结果在内存中保留：后续确认落盘或查询失败不能擦除此前已知事实，也不能因此记流程完整。

## 一个总预算，分开计数

新协调器使用材料层建立的**同一 Budget 对象和 1200 秒总期限**，覆盖存储/观察、两段认证、材料读取和退出；单个认证控制/收发仍最多 5 秒并取剩余时间。独立认证入口的默认 120 秒保持不变，不能将两个入口的默认值混写；新流程不在服务转换或材料开始时重置期限。

总接受额度为既有材料累计上限加 32 KiB 认证预留；单材料、固定请求数、帧和材料线路开销上限不改。固定认证序列完整时仍为 14,448 字节、31 次假调用（含最后 stop）。报告分别记录：

- `accepted_auth_bytes`：只计长度有效且预算接受的认证发送/读取；材料不会增加此计数。
- `accepted_payload_bytes`：材料载荷及 88 字节查询响应，不含认证；守卫缺失状态、协议头/状态字/排空另算。
- `accepted_total_bytes`：前两者之和，与共享 Budget 已用量一致。
- `accepted_wire_bytes`：既有材料协议所观察的请求/响应/排空字节；不包含认证，不表示实际 USB 线路流量。

异常/短包的真实传输量未知，不能从接受计数倒推已传多少。期限检查不能抢占阻塞的主机文件系统调用，真实设备超时和句柄语义仍待适配。

## 故障停止及只读检查

认证未知、半包、超时、中断或接收存储失败造成协议未知时，后续认证/材料/stop 均停止，只释放本地主机资源。认证或材料的 INTENT/ACK、材料记录、认证标记写入失败会冻结新流程，即使内存中曾知道完整响应也不补发退出；仅完整内容/格式拒绝且日志、期限及协议仍健康时允许一次退出。未知 stop 不查普通身份，不重发。

新报告为 `pipeline-report.private.json`、`a7c2-synthetic-authenticated-capture/1`；完整状态为 `SIMULATED_AUTHENTICATED_CAPTURE_COMPLETE`，其他为 `NEEDS_REVIEW`。报告包含接受计数、认证阶段、冻结状态及 false 边界，不含密钥、挑战、应答包、身份或绝对路径。真实认证、正常观察新鲜度、协议、机身、角色、恢复、写入和续跑仍未验证。

检查器新增第三种完整演练格式，保留此前两种。完成还须满足同一材料/确认顺序、在第二段认证后且首个材料前恰有一条有效原始认证标记、最终 31 次假调用/14,448 字节、计数加总、正常返回及未冻结状态；独立认证摘要不能升级为完整采集。缺 ACK 仍保留未确认意图，即使私人报告声称内存结果已知。它不重新运行认证或验证真实机身，哈希链仍不是签名。
