# N3：受限原始接口与句柄所有权的离线适配

第四十八轮新增 [captureraw](../lutphoto/captureraw.py)，把原始收发和单一关闭所有者接入[统一协调器](CAPTURE-PIPELINE-OFFLINE.md)。认证、固定材料请求/响应和 stop 使用**同一个模拟服务对象**，不再在该入口从独立 peer 直接取响应。公共入口仍只接受精确且全新的 SyntheticDevice/SyntheticPeer；**没有 USB 导入、枚举、真实句柄、MSC 接管、系统锁或设备 CLI**。旧三种演练和独立认证入口保留，未放宽其类型/指纹限制。

## 描述符与传输结果

固定 QAQLeonard/ma1co 来源显示，旧 GenericUsbDriver 从描述符寻找批量端点，没有固定输入/输出地址。新限制要求接口 0、备用设置 0，唯一的一个 bulk IN 和一个 bulk OUT；绑定后每次收发前后核对描述符未变化，不靠数组中的第一个候选猜测。测试里的端点数字都是自制输入，不能写成 A7C II 的实测端点。

普通接口沿用已审阅的 MSC `8/6/0x50`；服务接口暂要求 vendor class `0xff`，不臆定具体子类/协议值。描述符、端点唯一性和真实服务配置是否兼容尚未验证；额外端点、异常地址、类型/布尔值、接口变化均拒绝，不放宽到自动挑选其他配置。

| 边界 | 实现 |
| --- | --- |
| 控制请求 | 仅固定空载荷 start/stop；显式 int 0 才按主机传输契约接受，None/布尔/异常不算确认 |
| 发送 | 认证包只能为固定 516 字节；材料包由同一固定 OfflineChannel 生成。每次返回必须为精确完整字节数，短发送不补发 |
| 读取 | 只接受 bytes 或精确的 `array('B')`；先核对类型/长度上限，再转换不可变字节。不调用任意对象的转换方法；完整认证包/材料头、分块与单独排空规则沿用原模型 |
| 等待 | 每个原始读/写/控制都明确传入 timeout，最长 5 秒并取共享 1200 秒总期限的剩余时间；前后检查，不依赖 default_timeout 或重置期限 |
| 能力 | 内部认证视图只开放固定认证收发，材料能力只接受已验证频道的逻辑读取项；不返回含任意 write/temp/shell/reset 的 Session |

本轮只读核对已安装 PyUSB 1.3.1 的原始 write/OUT 控制返回计数、按长度 read 返回数组和 unsigned-byte buffer 实现，没有导入或调用它。支持这些返回形状不代表真实 PyUSB 连接/接口声明已验证；新模块本身只用标准库和既有纯主机模块，无新依赖。

## 一个所有者，关闭不重试

只有新私人 Store 成功创建、两个模拟端口完成装配后才由本次流程管理句柄；输入目录已存在、描述符/版本/类型拒绝时不接收或关闭调用方对象。空间预检失败发生在接收之后，会关闭两个本地模拟资源，不发送认证/材料命令。

认证与材料视图借用同一服务端口，没有析构关闭方法；只有所有者关闭。调用底层 close **之前**先使端口和所有借用视图失效，一次调用后不再尝试，即使返回不明或抛异常。正常初始句柄在服务观察前关闭；服务句柄在 stop 明确返回后、普通身份查询前关闭。异常路径也只释放本地资源，不 reset、清理机内状态、重认证或补发 stop。

关闭未确认不能记流程完整，已知 stop 结果仍保留；失败清理继续尝试另一个本地句柄，但不覆盖原始错误类型。日志/关闭记录失败同样冻结流程。这里的 SyntheticDevice.close 是**本地模拟释放契约**，不是已实现的 PyUSB Device 方法；未来真实释放必须独立绑定/审阅 dispose_resources、接口所有权和必要的恢复行为，不能拿这个假方法直接套真实设备。

正常返回仍由提供的假观察验证，没有新打开的真实普通句柄或新鲜协议查询。完整状态仍只为 `SIMULATED_AUTHENTICATED_CAPTURE_COMPLETE`；真实认证/机身/协议/正常观察新鲜度/系统锁/恢复/写入/续跑均 false。

## 日志与只读检查

沿用第三种 pipeline 报告格式，额外记录 `RAW_HANDLES_BOUND_MODELED` 和两个角色的 `RAW_HANDLE_CLOSED_MODELED`，不写端点、原始句柄、密钥、挑战、应答或机身身份。检查器只有在出现绑定声明时才要求恰好两项唯一关闭记录：初始普通认证确认后且服务观察意图前、stop 确认后且普通返回意图前；未确认动作和失败状态照常保留。原有无绑定声明的三种演练不因此获得真实接口证明。

完整认证仍为 14,448 个已接受字节、31 次认证视图调用，材料/认证计数分别保留且总量相加。异常时的调用计数不能证明底层已发送多少，线路/排空的真实身份和原子性仍未验证。日志链不是签名，检查器只核对现有证据，不执行认证或提供续跑。
