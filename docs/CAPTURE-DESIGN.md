## 首版设备能力：固定读取，不加载模块

首版设计优先复用已审阅的服务读取协议，**不需要为获得这批静态材料先上传 runtime/probe**。这能把 Sony ELF/BSS/加载生命周期问题留在后续原生执行阶段；不是断言读取路径已经实机验证。

- 正常 USB 仅用于 MSC/Sony 型号及身份查询；进入服务后只开放已审阅的 ProductInfo 读取、固定文件的 Jiritsu 15/17、RAM/保存快照读取，以及健康会话的一次退出。
- 文件路径由逻辑材料名映射，调用方不能传任意机内路径。固定 AP/CP 路径、68 个名称资源清单，以及必要的既有临时状态存在性检查分别列入白名单；存在旧 libJit/请求/结果或 preload 等未处理状态就停止，不清理它们。
- 不开放 Jiritsu 16/18、固件/设置写入、saveBackup、setBackupPresetData、setBackupId1、内存写入、挂载切换、WBI、预览重载、preload 或任意 shell。协议请求本身会写 USB 报文，不能将禁用文件写入称作完全无设备改动。
- 不继承上游初始 busy/no-media 后退入口。第一版要求正常身份可明确读取、物理端口完整、仅一台目标机身；未知/忙碌/既有服务状态在采集前停止，不靠临时模块补认型号。
- 采集器的接口只暴露固定读能力；不向调用方返回含 temp/write 方法的原始 Session。CLI/离线模块不得在导入时枚举 USB，真实适配器必须在以后明确的设备入口才加载。

后续如需原生型号/运行态/实际描述符证明，另设独立阶段：已有材料先排他保存并核验完整原厂程序，再审阅固定 worker、报告、加载范围和清理。不能把这个扩展悄悄加入首版读取流程，也不能从上游 runtime 输出直接把角色、捕获新鲜度或写入资格标为已证。

## 材料与主机保存

| 材料 | 固定范围与验收 |
| --- | --- |
| 完整 AP / CP | `/usr/lib/appFw.so` 99,960,744 字节；`/cp/cpapp-b.bin` 18,090,880 字节。首版只接受固定原厂 2.01 完整配对；混合、已改、截断均停止，不生成候选 |
| 初始 RAM / 保存快照 | 各不超过现有 BK4 解析器的 32 MiB；保留收到的完整原字节，再做受限格式检查。失败不截断、重编码或修复原件 |
| 结束 RAM / 保存快照 | 同样各有界并单独保留，用于观察本次读取前后的指定设置范围；运行组不要求全字节不变，不为消除差异而 save/reset |
| 名称资源（显式扩展） | 固定 68 文件，每项最多 1 MiB，按既有 UXC 契约检查；缺少时只形成核心采集材料，不能称完整导入材料已齐全 |
| 捕获记录 | 私人记录绑定作业号、阶段/时间顺序、身份观测来源/摘要、物理端口、每项完整 SHA/长度、源码锁和实际退出结果；不含写计划，不上传 |

首批程序在读取后立即排他保存，再识别完整配对；通过后才读取快照/资源。结束前完整重读 AP/CP 比较原始长度和 SHA，启用资源扩展时也复读全部 68 项，读回流可只保留比较结果而不再复制程序。初始和结束设置分别留证，不要求 RAM 与保存态相等才能保留原始材料；是否满足后续导入条件由独立设置检查判断。重复读取只验证观察到的内容一致，不证明这些文件来自同一个原子时刻或之后仍新鲜。

接收上限须在累计响应写入前实施，覆盖协议状态/头部开销；不能只给普通 BytesIO 加一次事后 len 检查，也不能任意放大 PMCA 的分包上限。单次调用与整个采集分别受期限和累计字节预算约束，不因新的一次 read 重置全程预算。响应大小异常、半包、超时或接收存储失败造成协议进度不明时，标记未知并停止，不排空/重发来恢复。

主机要求：仓库外、所属用户私有的新目录，逐层拒绝链接/非目录/所有者异常；使用已核对的目录句柄及排他创建，文件 0600、目录 0700。每项完整写入并 fsync、读回核验后发布记录，目录也同步；失败保留部分文件与阶段，绝不覆盖/自动续写。先检查可用空间但仍处理实际写满，未同步成功不记完成。额外副本是独立的离线复制/核验工作，不对相机重复采集；同卷、不同 APFS 卷或 st_dev 不同均不能单独证明物理介质独立。

角色不自动判定：旧 core 按扫描顺序给两个 BK4 块编号，当前本地解析器要求明确角色断言；旧 CP 直接读仅覆盖两个键，N3 保护范围有四个，不能借这两个值的相等声称完成四项或芯片归属证明。首版先保留原件及观测来源；角色/外层容器未证时保持未证，不暗中给后续 CLI 填入 0/1。

## 执行状态与异常边界

以下是设计状态，当前没有这些命令或状态文件：

| 阶段 | 继续条件/结果 |
| --- | --- |
| C0 主机预检查 | 固定源码/原厂策略、新私人输出、空间、用户实际菜单版本/电量及设备范围明确；新采集电量拟沿用项目至少 50%，实现时独立验证，不混用官方更新的 51% |
| C1 全局独占与普通身份 | 在枚举/卸载前持有与旧工具相同的系统锁，随后持有作业锁；固定获取顺序，不删除锁文件；正常卸载、型号/身份/物理端口均明确 |
| C2 服务认证 | 两段认证和转换使用固定端口；任一结果未知停止。不得因目标 PID 重现就重认证或接受另一台机身 |
| C3 程序材料 | 完整 AP/CP 已排他保存，原厂配对匹配后才进入快照/资源阶段；匹配失败不补丁化程序或重填指纹 |
| C4 材料及观察完成 | 请求的原件逐项持久化、格式检查、程序/可选资源复读及结束快照完成；缺项/变化保留证据，不能进入部署 |
| C5 健康退出与普通身份复核 | 仅在协议健康时单次退出服务，正常 MSC 返回后重新核对同一端口及同一种身份观测；PID 返回本身不够 |
| 完成本次材料采集 | 只表示请求材料及退出符合采集契约，不表示角色/外层备份/原生运行/恢复/独立介质/部署已验证；关闭设备句柄后再给人工动作提示 |

全局锁必须贯穿设备操作、退出及主机证据发布；原型锁不替代它。旧工具、采集器和未来导入器统一使用旧系统锁，不修改旧实现；独立工具不遵守该锁仍可能冲突，需要在操作前关闭。

必须分清三种失败：进入服务前的主机/身份拒绝；响应完整且链路健康时的内容验证失败（可单次受控退出）；超时、中断、半包、认证/协议未知（只释放主机资源，不再发 stop/清理/重试）。服务 stop 返回不明、普通 USB 超时、返回身份不符、主机证据同步失败均不得记完整成功。新流程先统一保留 needs_review，不套用旧 prepare 的特定 usb_unconfirmed 续接条件。

## 下一步实现与验证

第四十二轮已实现**纯主机采集状态/存储层及假传输演练**，不导入 USB、不打开系统相机锁、不创建真实设备命令。完整/部分材料、原厂指纹拒绝、并发/链接/写满/同步失败、接收超限、复读变化和退出未知已有自制测试，真实来源正例仍缺。第四十三轮进一步实现固定请求和累计协议预算的被动模型，不执行传输，保留响应头限制/排空边界缺口。第四十四轮已装配[离线会话协调](CAPTURE-SESSION-OFFLINE.md)，覆盖同源身份/端口、逐请求日志、假认证/退出、固定守卫和锁顺序。实际系统锁/USB 尚未接通，且固定 PMCA start/stop 会吞掉一类 USB 异常，须单独审阅错误传播。第四十五轮已有[旧演练目录只读检查](CAPTURE-INSPECTION.md)，不升级模拟验证或提供续跑许可。下一步离线适配认证错误传播，不把模拟后端直接换成真实 Session。

真实材料/角色/容器兼容、无模块读取在原厂机身上的行为、捕获来源及独立介质仍无实机证据。完成离线层和设备适配器审阅后，再一次性说明连接、实际电量、权限及服务操作范围并进入获准的采集；当前不需要相机、Docker 或惠普电脑。写入/恢复仍属后续 N3/N4，见[总计划](../plan.md)与[当前交接](../research/HANDOFF.md)。
