# A7C II 功能扩展可行性评估

评估日期：2026-10-18。代码基线为本仓库 `5babef40bba986efdd0573380c0ff9f8a027495c`，固定上游为 `dd01c07a2a5df004d709595a43ebafe81bbd8fae`。本次只阅读源码、查询公开一手资料和运行离线测试，没有连接或操作相机，没有改动功能代码、上游资产或锁文件。

**建议继续开发，但先把目标限定为“直出配方管理，以及有明确证据支持的色彩扩展”。** 现有项目可以复用备份、USB 会话、完整指纹检查和验证机制；它还不具备通用的机内插件接口。对于任意照片 LUT、新拍摄算法或大幅视频规格提升，目前只能做研究立项，不能承诺实现。

上游源码位于完成资产展开后的 `.upstream/a7c2_fl23_preview/`。本评估同时核对了其 `core.py`、`app.py`、`transport.py`、`native/installer.c`、`native/runtime.c`、`BUILD.md`、许可和补丁清单。

**主要工程限制是功能专用逻辑分布在多层。** `core.py` 写死原版/候选完整哈希和目标键，`transport.py` 限制可写单元与临时文件，原生安装器编译进固定窗口表，runtime 固定检查六处区域。Mac 适配层继承了上游安装、参数保存和恢复流程。新增功能要同步设计全部检查与恢复路径，不能只改 JSON、放宽白名单或替换一项哈希。

机内代码可以临时执行，只证明这个入口可用；不能由此推断已经能够在正常拍摄时安全挂接按键、访问实时图像帧、调用成像算法或控制镜头。当前仓库也没有完整 Sony 应用/图像处理源码。[上游研究](https://github.com/QAQLeonard/a7c2-fl23-research/tree/dd01c07a2a5df004d709595a43ebafe81bbd8fae)与[服务入口研究](https://github.com/YuuLuo/a7c2-service-preload)可用于追溯背景，后者的 preload 方案不是本工具正在使用的运行方式。

## 先扣除相机已经具备的功能

- **外观配方：** 官方支持十种基础 Creative Look、八项调整和六个自定义外观槽。配方库可以整理这些设置；只有扩大机内槽位、增加名字或加入新的底层色彩模型才属于额外的机内能力。白平衡、曝光补偿等应作为配方的独立字段，不能假设它们跟随 Custom Look 槽一起保存。[Sony Creative Look 手册](https://helpguide.sony.net/ilc/2360/v1/en/contents/0411B_creative_look.html)
- **对焦包围：** 已能设置步幅和拍摄张数。新增价值可以是按实测焦点组织拍摄、自动整理素材和电脑合成；不能把“拍出一组包围照片”包装为新解锁能力。[Sony 对焦包围手册](https://helpguide.sony.net/ilc/2360/v1/en/contents/211h_focus_bracket.html)
- **间隔拍摄：** 已有间隔、张数、曝光跟随等设置。更复杂的时序、任务队列和跨任务曝光控制可以另做联机工具。[Sony 间隔拍摄手册](https://helpguide.sony.net/ilc/2360/v1/en/contents/0407P_interval_shoot_setting.html)
- **设置备份：** 原机能在存储卡保存/加载设置；它不包含所有设置，例如自定义白平衡、网络和语言等有例外，也存在型号/版本限制。产品机会是比较、分类和版本管理，而非重新通过服务接口复制整份机身设置。[Sony 设置保存/加载手册](https://helpguide.sony.net/ilc/2360/v1/en/contents/0601_save_load_settings.html)
- **视频 LUT：** 已能登记用户 LUT，接受 17/33 点 CUBE。PPLUT1–PPLUT4 在官方手册中明确限定为拍摄动态影像；“导入视频 LUT”不能作为“照片任意 LUT 直出”已经可用的证据。[Sony LUT 管理手册](https://helpguide.sony.net/ilc/2360/v1/en/contents/211h_manage_lut.html)、[Sony 图片配置文件手册](https://helpguide.sony.net/ilc/2360/v1/zh-cn/contents/0412D_picture_profile.html)

## 候选功能与优先级

下列可行性是基于源码与官方接口的工程判断，不是新功能已经实现或实机验证。P0 为下一阶段优先项；P1 为有条件开发；P2 为限时探索；暂缓项不纳入交付承诺。

| 候选功能 | 推荐实现方式 | 脱离电脑能否使用 | 判断与优先级 |
| --- | --- | --- | --- |
| 直出配方库、参数校验、场景分类和设置卡 | Mac 端管理，先按原机菜单手动录入六个槽；包含 Look 八参数、独立白平衡和曝光建议 | 能，录入后按原机能力使用；部分参数须单独切换 | 可行性高，P0；首版不依赖新固件修改 |
| 配方一键同步、切换前后设置比较 | 先确认官方 SDK 对 2.01 的具体属性读写支持；不能写的字段给出手动步骤 | 成功写入并保存的设置可留在机内，需验证持久化 | 条件可行，P1；自动同步目前没有证据覆盖全部字段 |
| 官方视频 LUT 的整理、格式检查和导入指引 | Mac 检查 CUBE 文件，再走原机存储卡导入流程 | 能，用于原机支持的视频模式 | 可行性高，可并入 P0；不称作新的照片滤镜 |
| 在已有扩展位置研究自定义色彩/曲线 | 先在电脑解析与验证数据，再限于已理解的色彩模型做候选 | 若专项补丁成功，能 | 有研究基础，P1；须解决当前合并函数拒绝已占用槽位、绑定与恢复问题 |
| 新增更多具名 Creative Look、扩充六个自定义槽 | AP 菜单/资源/存储与 CP 编号、边界、元数据共同逆向 | 若实现，能 | 尚无完整证据，P2；空闲字节或表尾空间不证明功能可扩展 |
| 完整的 FL2/FL3 视频外观 | 单独分析 CP 视频处理与参数路径 | 若实现，能 | 尚未验证，P2；当前补丁有 movie fallback，不能拿照片成功代替视频支持 |
| A/B 焦点预设、自动拉焦、拍摄序列 | Mac 经官方 SDK 使用对焦位置与拍摄接口 | 不能执行由 Mac 编排的任务 | 有官方接口依据，P1；需按机身和镜头测量，不保证绝对距离或电影镜头级轨迹 |
| 更复杂的曝光/间隔序列、拍后对焦合成 | 官方遥控拍摄加电脑任务调度、图像合成 | 任务执行/合成依赖电脑 | 值得开发，P1；与原机已有包围/间隔功能形成补充 |
| 电脑实时监看上的假色、直方图、构图参考 | 官方实时取景加 Mac 图像处理 | 不能显示在机身屏幕上 | 条件可行，P1；取景格式、帧率和延迟需先实测 |
| 任意照片 3D LUT、实时颗粒、机内合成或新插件菜单 | 研究照片处理链、图像缓冲、UI 和拍摄时机 | 目标是能，当前未建立实现路径 | 高不确定，P2；颜色矩阵/曲线表达能力不等同于任意 3D LUT 或空间效果 |
| 全画幅 4K60/4K120、更快连拍、新 AF 算法等 | 涉及传感器、处理器、带宽、算法与热管理的系统工程 | 未有本项目证据 | 暂缓；现有补丁不能证明这些限制可由软件开关解除 |

官方 Camera Remote SDK 明确列出 ILCE-7CM2 和 macOS，并记载其对焦位置读写支持，需要预先学习机身/镜头的设置值；2.00 及以后固件的该映射还发生过变化。因此，焦点预设的技术依据强于机内新增插件，但仍需镜头校准和真实连接验证。具体属性、接口和平台兼容性应以申请取得的 API 文档及样例为准，不能把整个 SDK 的功能列表套给这一机型。[Sony Camera Remote SDK](https://support.d-imaging.sony.co.jp/app/sdk/en/)

另一条 Camera Remote Command/PTP 路线也列出此机型，但官方页面说明其资料仅向企业客户提供；不能假设个人可以直接取得。选型时先确认实际可获得的 SDK/文档和许可，不绕过申请流程。[Sony Camera Remote Command](https://support.d-imaging.sony.co.jp/app/cameraremotecommand/en/index.html)

## 推荐的第一版

第一版做成 **“A7C II 直出配方管理器”**，形成一条不依赖新增刷写的可用路径：

1. 本地保存配方：基础 Look、八项调整、白平衡模式/色温/偏移、曝光建议、适用光线与示例照片。
2. 区分原厂外观与依赖 FL2/FL3 的配方；让用户明确选择其可用外观，不借机触发安装或服务诊断。
3. 显示六个机内槽的录入清单，校验参数范围，分别说明不随槽切换的设置。首版以手动录入形成完整交付。
4. 对同一批用户照片做并排比较；预览若只是电脑近似处理，明确标注，不能宣称等同机内 JPEG。
5. 保存/导出应用自己的配方 JSON 与可读设置卡。不要把应用 JSON 伪装成 Sony 可加载的设置文件；首版不编辑未理解的官方设置文件。
6. SDK 条件满足后，再补属性探测、切换前比较、有限字段同步和读回；不因缺少官方接口而回退到任意服务参数写入。

这样可以先积累真实使用需求与固定场景样张，再判断是否值得为新色彩模式承担固件逆向与验证成本。若用户的硬性目标是“脱离电脑后，机内多出新的滤镜名字/算法”，这个第一版只提供配方管理价值，仍需下面的机内研究阶段。

## 机内扩展应怎样组织

**保留当前安装器的固定边界，另建离线研究工具目录和独立实验版本。** 现有 `AGENTS.md` 限定原版 2.01、固定指纹及上游资产，本次不改动这些约束。未来的新功能要作为独立版本评审，不能通过更改旧锁文件来冒充原先验证过的补丁。

建议先补足以下能力，再进入新功能写入：

- **补丁身份和迁移关系。** 标识固件、补丁版本及组合状态；区分“原厂”“FL2/FL3”“指定色彩实验版”。只接受明确验证过的来源与目标，不叠加未知补丁。现在已安装 FL2/FL3 的机身会被原版 prepare 和空槽检查拒绝，没有通用增量安装路径。
- **确定性的离线候选生成。** 保留原字节、长度、范围不重叠、完整哈希、反向还原和不涉及旧色彩记录的检查；扩展到 C 头文件、模块与资源之间的一致性检查。跨版本重新定位作为单独工作，不做“强制兼容”。
- **原生构建与可审计验证。** 上游 `BUILD.md` 给出 Zig 0.13.0 的 AArch64 编译方法；本次没有重编译或独立验证二进制可重现性。新模块需要重建、结构检查及适当仿真；现有 Python 测试不能代替原生模块故障注入。
- **覆盖新增目标的验证与恢复。** 新增窗口要有对应运行期证据；色彩变体要核对当前/保存参数与占用关系，并保留机身校准。每个已知组合状态都需要可验证的恢复目标。恢复能力仍不等于未知部分损坏或无法开机时可以救援。
- **受限故障研究。** 现有 `writing_settings` 非目标属性变化应继续追查原因、保留属性差异和失败阶段；不能直接新增白名单。专项 diagnose 没有推进安装或 WBI 收尾的能力。

本仓库验证记录只证明通用版 verify 曾在一台已安装机身运行；通用版首次 prepare、install、restore 与新增 diagnose 均不能据此视为实机通过。这是后续持久化修改的基础验证缺口，建议在专用测试机上先补齐，再扩大补丁范围。[验证记录](VALIDATION.md)、[中断安装诊断边界](INTERRUPTED-INSTALL.md)

联机功能应使用独立的普通遥控会话，和服务模式互斥。不要让同一界面后台同时运行 SDK 遥控与补丁安装。Sony 文档要求遥控组件与相机固件满足其支持条件；若未来官方接口需要升级固件，应先评估与固定 2.01 补丁的冲突，不能自动升级已有改装机身。

## 工作量与阶段出口

以下是规划区间，不是报价或成功概率。假设由一位熟悉 Python/macOS 的开发者持续投入；机内阶段还要求具备固件逆向能力、取得合法分析材料并使用专门测试机。SDK 申请、硬件等待和未知故障排查不计入确定交期。

| 阶段 | 粗略投入 | 可以承诺的产物/出口 |
| --- | --- | --- |
| P0：配方管理首版 | 约 5–10 个工作日 | 配方编辑/导入导出、设置卡、范围校验、手动录入说明；不承诺自动写入或精确色彩模拟 |
| P1a：官方联机探测与小原型 | 取得 SDK 后约 3–5 个工作日 | 实测型号/版本/属性支持表；只选择确认支持的下一项功能 |
| P1b：一种联机功能 | 探测通过后约 1–3 周 | 例如 A/B 焦点或拍摄队列；要包含取消、超时、状态读回及素材核对 |
| P1c：现有色彩记录的离线研究 | 先限制为约 2–4 周 | 数据结构说明、可复现候选和仿真/不变量检查；若找不到充分证据则停止，不把限期变成上机期限 |
| P2：新增菜单槽、视频 FL2/FL3、照片任意 LUT | 先用约 4–8 周做其中一个方向的可行性研究 | 输出处理路径、关键未知和可继续/应停止结论；正式交付工期暂不估算 |

推荐顺序：**配方管理 → 官方接口能力探测 → 选择一种联机功能或受限色彩实验 → 评审是否进入新增菜单/算法研究。** 联机路线不满足脱离电脑使用的硬性需求时，可以跳过联机功能开发，把预算留给机内研究，但应保留其不确定性。

机内实验进入下一阶段的最低证据包括：精确原版和候选匹配、与旧外观/设置隔离、冷启动后的目标运行内容、固定白平衡/曝光下的对照样张、JPEG/HEIF 与 RAW+JPEG 等受影响组合、照片标识与回放、视频模式切换回归，以及对应已知状态的恢复验证。照片色彩测试应覆盖不同光源、肤色、高光和阴影；不由一张样片决定“移植等同原厂”。断线/断电故障先在仿真中注入，不在日常使用的机身上主动制造损坏。
