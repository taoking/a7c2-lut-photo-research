# N3：认证与退出错误传播的离线适配

第四十六轮新增 [captureauth](../lutphoto/captureauth.py)，在精确的 SyntheticDriver 假驱动上实现固定来源的原始认证报文、长度/状态检查和一次退出。**没有 USB 导入、枚举、真实句柄、系统相机锁或设备 CLI。** 独立入口仍保留；第四十七轮另有[认证/材料统一离线协调器](CAPTURE-PIPELINE-OFFLINE.md)，没有接入真实材料采集，不支持把假驱动替换成真实 Session。

## 固定来源与兼容依据

来源为 QAQLeonard v2.1 `7e54d60b458847f1befa6cfd614fbf004b8b0b90` 包中的 ma1co Sony-PMCA-RE；纯 SHA-1 源码另注明 ajalt/python-sha1。保留[署名及许可](../ACKNOWLEDGEMENTS.md)，新增独立的 [9 成员来源清单](../research/upstream-auth.lock.json)，覆盖认证、常量、哈希、两层 USB 包装及许可。整包 SHA、各成员长度/SHA/Git blob 与既有 10 成员加载链锁共同核对；旧安装器、旧锁、依赖和默认单份备份不改。

生产实现只对固定常量源码做 AST 字面量解析，三组 SHA-1/三组 SHA-256 密钥仅留内存，不导入或执行归档模块，不复制到仓库或报告。独立实现兼容的哈希压缩：填充使用完整消息长度，尾部长度字段使用 `(原消息字节数 & 31) * 8`；不能误写成对比特数取掩码或直接用标准 SHA-1 处理长消息。

本轮额外离线对照**执行了固定、已审阅的三个纯主机哈希函数**，只提供 struct、len、range；未执行归档设备模块、USB 或目标代码。它用于独立比较 13 种自制长度及完整模拟应答，不属于生产路径，也不能称为“本轮完全没有执行归档代码”。

## 报文及严格传输结果

| 项目 | 离线实现与拒绝规则 |
| --- | --- |
| start / stop | 固定 OUT/VENDOR/OTHER 控制请求；空载荷必须返回精确 int 0。None、布尔值、非零或异常均停止 |
| 认证包 | 大端 `>HH512s`，516 字节；发送命令取反、salt 为 0；单次发送必须返回精确 int 516，不重发短发送 |
| 响应 | 一次读取返回精确的不可变 bytes 516 字节；不拼接短响应、不接受额外字节或可变数组。解码状态按固定源码先取反再减 salt，允许合法非零 salt |
| 三轮应答 | 每轮请求 1 接收状态 2/8，按轮次选择 SHA-1/SHA-256；普通 PID 使用挑战前 4 字节，服务 PID 使用完整 512 字节挑战加该轮密钥。请求 3 的载荷为 1 加摘要，必须返回状态 4 |
| 最终认证 | 请求 5 必须返回状态 6 且载荷首字节 1；任何错误状态或结果不完整均不能继续或退出 |
| 全程预算 | 默认两段认证/退出共 120 秒、32 KiB 已接受认证字节，单次调用最长 5 秒且不得超过剩余期限。发送/读取前检查额度，前后检查期限，第二段不重新计时 |

固定上游 start/stop 捕获 GenericUsbException 后返回；GenericUsbDriver 和 libusb 包装层还丢弃发送/控制传输的字节数。新模型直接要求显式原始结果，**没有把这些旧方法的 None 或“没抛异常”视为确认**。这些严格要求是否与真实相机及未来原始 USB 接口兼容仍未实测；本轮没有改旧行为来获得通过。

`accepted_auth_bytes` 仅计算长度有效的认证发送/读取；完整双阶段为 28 × 516 = 14,448 字节、31 次原始假调用（含三次控制请求）。它不是实际线路流量：异常或短包的未知传输不能据此倒推出总字节，控制请求头开销及将来的材料读取也不在此计数中。

## 持久化与一次退出

每次 start、整段三轮认证、stop、正常返回核对分别先同步 INTENT，动作返回后才写 ACK；不是每个认证子报文单独记录。任一子报文未知都会停止整段，不允许以此日志重放其中某一轮。

INTENT 写入失败不发送相应动作，并冻结当前流程。动作失败/超时/中断/长度或状态异常时标记未知，禁止后续认证、退出、清理或重试。完整返回但 ACK 落盘失败时保留内存中的已知阶段，同时冻结；不能因为确认缺失再次发送。

stop 仅在两段认证成功、同端口服务转换符合条件且流程健康时允许一次；持久化意图后、调用前消费退出许可。`STOP_CONTROL_RETURNED` 只代表假控制传输按主机契约返回，不能证明相机已退出服务。`SIMULATED_AUTH_COMPLETE` 还要求提供的普通身份、来源、型号、总线/物理端口及唯一性与初始自制观察一致；本模块没有重新查询设备，也不证明观测新鲜度。

报告只包含有限状态、计数、固定源码身份与 false 边界，不含路径、机身身份、密钥、挑战或应答包。摘要为私人证据；真实认证、协议、机身、正常观测新鲜度、全局锁、恢复、写入和续跑仍 false。Store 的私人作业锁不代替系统相机锁。

## 验证与下一步

专项命令：`.venv/bin/python -B -m unittest research.tests.test_captureauth -q`，34 项通过；完整命令及整套回归见[第四十六轮](../research/LUT链路调查记录-第四十六轮.md#实际测试命令与结果)。测试使用自制密钥/挑战，不依赖未发布的归档或相机。

覆盖独立报文预期、两种哈希/混合轮次/非零 salt、短包/短发送/异常/中断、总期限、同端口转换、日志失败、退出不重发和无设备导入。实际固定归档对照另有 13 个纯哈希长度和 8 个假驱动场景，密钥/原包不写入报告。

第四十七轮已连接本认证、既有固定材料流程与检查器，见[统一离线协调器](CAPTURE-PIPELINE-OFFLINE.md)。它共享 1200 秒总预算且认证/材料分别计数，不重置本独立入口的默认 120 秒；内部正常查询在持久化意图之后发生。[只读检查器](CAPTURE-INSPECTION.md)识别新的第三种完整演练格式；本模块单独的认证摘要/日志仍不是完整材料证据。第四十八轮另有[同模拟句柄受限接口](CAPTURE-RAW-OFFLINE.md)，只通过内部阶段复用认证逻辑，未放宽本模块公共入口对精确 SyntheticDriver 的要求，也不能接收真实后端。

受限 USB 接口、MSC 接管/重挂、真实全局锁和句柄生命周期继续独立开发/审阅，真实响应/回显/排空另需受控观测。材料角色/外层容器/新鲜来源、完整事务、bound worker、恢复及独立介质仍缺。当前无需相机、Docker 或惠普电脑；真实操作进入前提示，不能运行 prepare/diagnose 代取材料。
