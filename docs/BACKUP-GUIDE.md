# 原厂相机：日常备份、官方升级与开发材料

适用于尚未建立开发备份的 ILCE-7CM2。本文说明手动操作顺序；不代表已经执行备份、更新或实机验证。核对日期：2026-10-20。

## 先保存照片和日常设置

1. 在相机中选择 `MENU → 设置 → 重置/保存设置 → 保存/加载设置 → 保存`，选择新增保存，保留已有设置。模式旋钮须在 1/2/3 之外，例如 A 或 P。菜单依据[索尼中文帮助指南](https://helpguide.sony.net/ilc/2360/v1/zh-cn/contents/0601_save_load_settings.html)。
2. 正常关机，等待存取灯熄灭后取卡，用读卡器连接 Mac。在仓库之外新建私人文件夹，例如“图片/A7C2-日常备份-日期”，复制存储卡的全部可见文件和文件夹，保留原来的目录结构，包括照片、视频和刚保存的设置；不要只复制 DCIM。
3. 在 Mac 上核对复制完成、文件数量和大小，并打开需要保留的照片/视频检查。这个步骤只是日常文件检查，不证明内部开发备份或完整恢复能力。确认保存成功前，不删除卡上的原文件，也不格式化。
4. 自定义白平衡、网络等不能由该菜单完整保存，重要设置另外自行记录；完整排除项见[官方说明](https://helpguide.sony.net/ilc/2360/v1/zh-cn/contents/0601_save_load_settings.html)。文件留在本地，不上传仓库或聊天。

卡上设置是普通菜单设置文件，不包含完整 AP/CP 程序、RAM/保存 BK4 快照或 68 个 UXC 资源，不能直接用于[开发材料检查](IMPORT-MATERIALS.md)。索尼提示不同固件版本的设置可能无法互相加载；保留升级前副本，不能承诺升级后可完整导回。

保留 Ver.2.00 可以继续所有当前离线开发，是否升级留到设备阶段决定。卡副本不是 2.00 内部固件镜像，也不证明可以降级。若后续选择第三方修改升级包的部署路线，须先固定具体仓库/版本、产物及迁移/恢复链单独审阅；现有原厂 2.01 服务流程的检查不能自动用于该路线。

## 决定升级时，使用索尼官方 Ver.2.01

目标型号是 **ILCE-7CM2**，目标版本写作 **Ver.2.01**。官方操作和下载入口：[索尼中国 Ver.2.01 存储卡升级说明](https://service.sony.com.cn/download/firm/00003056.html)。先阅读官方全文，以下仅归纳顺序：

1. 先完成上面的文件备份。优先使用另一张无重要资料的兼容存储卡；按官方说明在相机中格式化升级卡。**格式化会删除卡内全部内容，包括刚保存的设置。** 仍使用原卡时，先确认照片、视频和设置均已复制到电脑。
2. 使用充满电的 NP-FZ100。官方升级门槛为至少 51%，与旧 FL23 工具的 50% 门槛不同；不代填或猜测实际电量。相机过热时先等待降温。
3. 从上述官方页面下载 `BODYDATA.DAT`，保持文件名，把唯一的一份放到升级卡根目录。官方标注文件大小为 1,139,929,560 字节；大小相符不能替代官方来源或安装后的程序指纹核验。
4. 将卡放回相机，进入 `MENU → 设置 → 设置选项 → 版本 → 软件更新`。核对下载型号为 ILCE-7CM2、屏幕当前版本及目标版本正确，目标为 2.01，再按官方提示执行。更新期间保持电源开启，不取电池或存储卡；黑屏及指示灯闪烁可能是正常进度，官方预计约六分钟。
5. 等待自动重启并确认完成，再查看机身版本确为 **Ver.2.01**。记录实际结果，不能把计划升级或已下载文件记成更新成功。异常按官方对应说明处理；不把其他错误或任意黑屏当成可以取电池的依据。

本文未下载或分发固件，没有执行更新。官方更新不等于安装第三方 LUT，也不证明本仓库首次备份或恢复已经实机通过。

## 内部开发备份另行处理

| 内容 | 当前入口与边界 |
| --- | --- |
| 照片、视频和菜单设置 | 上述相机菜单及读卡器手动复制；不需要本仓库服务模式工具 |
| Ver.2.00 内部程序/设置采集 | 当前项目不支持；不调用旧 prepare、诊断或其他设备命令试读，不修改版本/哈希来放行 |
| Ver.2.01 内部开发材料 | 菜单版本只是先决条件；仍须精确匹配完整程序指纹，并有经过审阅的采集流程和相应设备操作授权 |
| 本人已有开发备份 | 仅在本人明确给出的路径内只读检查；不搜盘、不混用其他机身材料，不把日常设置文件改名充当 BK4 |

真实 CLI 没有独立的 `backup` 子命令。旧 `prepare` 在服务模式中读取设置/程序、制作 FL2/FL3 候选，并执行临时机内预检查；完整指纹拒绝发生前已可能有设备读取。它不是通用的中性文件复制工具，不能把“让它报错”当成采集 Ver.2.00 材料的方法，也不为新 LUT 研究直接运行。实际行为见[工作流源码](../macfl23/workflow.py)及[验证边界](VALIDATION.md)。

专用内部采集入口尚未交付。[第四十一轮设计](CAPTURE-DESIGN.md)已离线审阅版本/身份门槛、固定读取范围、主机排他保存/完整性、服务退出及异常停止：首版以服务协议读取为目标，不上传原生模块。第四十二轮已有纯主机状态/存储与假传输测试，第四十三轮增加[固定请求与被动协议模型](CAPTURE-PROTOCOL-OFFLINE.md)，仍没有真实读取；第四十四轮已有[会话协调演练](CAPTURE-SESSION-OFFLINE.md)，仍不执行真实认证或打开系统相机锁；第四十五轮已有[旧演练目录只读检查](CAPTURE-INSPECTION.md)，不提供真实采集/恢复或续跑许可；第四十六轮另有独立[认证/退出离线适配](CAPTURE-AUTH-OFFLINE.md)，第四十七轮已在[统一离线协调器](CAPTURE-PIPELINE-OFFLINE.md)连接自制材料流程，尚未接入真实读取。满足条件后一次说明所需连接、电量、系统授权及服务操作范围。自制传输演练不会备份相机；升级意愿不等于已完成升级、已获得内部材料或已验证恢复。

旧 FL23 流程仍默认单份备份；新 Custom LUT 持久化写入前的两份独立介质完整备份门槛另行核实，日常卡文件副本不能计作该内部备份，备份也不保证救回无法启动的机身。当前不运行 prepare/install/restore/diagnose 或任何 USB 命令。
