# A7C II LUT 拍照开发可行性与专利核查

评估日期：2026-10-18。目标：在 A7C II 上使用自选 LUT 拍摄静态照片，优先考虑脱离电脑仍能使用的机内功能；用途为学习研究和个人使用。

本轮只审阅现有源码与公开资料，没有连接相机、读取私人备份、下载新固件、反汇编定位照片管线或制作补丁。本报告是立项评估，不能作为功能已经实现或法律风险已经排除的证明。

## 1. 结论

**可以继续做学习研究，现阶段建议先开展有时间上限的调查，不能承诺机内 LUT 拍照一定能实现。** “因为专利所以索尼不能做”的说法，尚未找到 Sony 官方说明支持；确实存在相关松下专利，但需要按地区、有效权利要求和具体实现分析。

技术上的首要未知是：A7C II 已有的视频 LUT 引擎，能否接入全分辨率静态照片输出。现有 FL2/FL3 成功说明该机型能扩展特定内建外观，不说明它已经支持任意 `.cube`。

建议先投入 **5–10 个有效工作日**做离线调查，以“找到静态照片处理入口及可复用 LUT 调用”为继续开发的门槛。没有找到之前，不按隐藏菜单解锁项目报价，也不在日常使用的相机上试写。

## 2. 官方能力与目标之间的差距

| 能力 | 查到的事实 | 对本需求的意义 |
| --- | --- | --- |
| 用户 LUT 管理 | A7C II 可注册 User1–16，支持 17 点、33 点 `.cube` | 已有导入和存储机制可供研究，不能据此推导照片支持 |
| PPLUT1–4 | 型号专属手册明确限定于拍摄视频 | 官方支持范围不包括将这些 LUT 写入静态照片 |
| Display LUT | 文本说明用于视频拍摄、回放的效果预览 | 监看变化不等于 JPEG 像素发生变化 |
| 本项目 FL2/FL3 | 使用固定程序补丁和特定外观参数 | 可复用安装保护经验，不能直接复用为通用 LUT 引擎 |

官方依据：[A7C II LUT 管理](https://helpguide.sony.net/ilc/2360/v1/en/contents/211h_manage_lut.html)、[Picture Profile](https://helpguide.sony.net/ilc/2360/v1/en/contents/0412D_picture_profile.html)、[Display LUT](https://helpguide.sony.net/ilc/2360/v1/en/contents/211h_display_lut.html)。Picture Profile 页面直读超时，本轮通过搜索返回的该官方页面正文核对了视频限定。

上述手册是当前公开说明，并非已对原版 2.01 的全部行为做了实机确认。不能从菜单名称或当前手册倒推出某段特定固件代码的位置。

本需求应分成三个独立验收目标：

1. 拍摄前，机内屏幕能预览所选 LUT 的效果。
2. 按下快门后，完整分辨率 JPEG 的像素确实经过 LUT，回放与缩略图一致。
3. 断开电脑、正常关机及冷启动后，前两项仍能使用。

只做到菜单显示、视频效果、EXIF 标签变化或电脑后处理，均不能算完成这三项。第一版优先限定 JPEG 单张、单 LUT、明确输入/输出色彩空间；RAW 文件保留作为独立影像来源。HEIF、HDR、连拍、双 LUT 和更广模式兼容性另行验收。

## 3. 当前代码能提供什么

审查基线：本仓库 `5babef40bba986efdd0573380c0ff9f8a027495c`；固定上游 `dd01c07a2a5df004d709595a43ebafe81bbd8fae`。

- [Mac 适配层](../macfl23/workflow.py)和[固定上游加载器](../macfl23/engine.py)提供备份、身份/指纹检查、状态管理及部署资产校验经验。
- 上游 `core.py::patch_program()` 只接受固定原版/目标完整哈希，实际清单为 AP 8 个、CP 32 个固定写入窗口。`merge_colors()` 只处理参数 55/56、槽位 23/25。
- 每个新增色彩记录包含 64 字节 chroma 和 576 字节 matrix；不能仅凭字段名把它解释成通用 3D LUT，现有代码也没有 `.cube` 解析、任意 LUT 上传或照片像素处理回调。
- `native/probe.c` 是经服务接口加载后返回的一次性模块；`native/runtime.c` 核对六处固定区域。它们不是可在正常拍摄时常驻运行的应用框架。

为说明表示规模：若采用三个 RGB 通道各 16 位的密集表，17³ LUT 为 29,478 字节，33³ 为 215,622 字节。此为数学计算，不是 Sony 内部格式测量；640 字节外观参数不能未经分析就当作任意 LUT 的等价载体，部分简单映射是否可拟合仍需实验。

新增机内功能需要独立补丁清单、候选哈希、部署状态与恢复设计。现有 `restore` 针对已知 FL2/FL3 候选，不能自动恢复未知 LUT 补丁。已有 FL2/FL3 机身与原版机身也必须分别定义支持基线，不能通过放宽旧哈希检查混用。

补丁研究与机内执行机制来自 [QAQLeonard 上游](https://github.com/QAQLeonard/a7c2-fl23-research)，本项目负责 macOS 适配。现有安装、验证、恢复的实测边界仍以 [VALIDATION.md](VALIDATION.md) 为准。

## 4. 技术路线比较

以下工作量是工程判断，按熟悉相应技术的单人有效工作时间估算，不是已经验证的工期；不包含等待用户试机、设备维修或未知硬件问题。

| 路线 | 可行性判断 | 能达到的体验 | 估计与主要未知 |
| --- | --- | --- | --- |
| 复用视频 LUT 引擎，接入照片管线 | 值得优先研究；实现尚不确定 | 有机会同时实现机内预览和 JPEG 直出 | 先调查 5–10 天；若证明可复用，实验原型再约 2–6 周；稳定化另算 |
| 将部分 LUT 拟合为创意外观参数 | 受限方案，需先解析参数语义 | 可能实现近似色彩，难保证任意 LUT 一致 | 数周起步；必须量化误差，不能宣传为完整 `.cube` 支持 |
| 在相机内对已拍 JPEG 再处理 | 目前缺少拍摄事件、运行及文件管理机制 | 若成功，可拍后生成副本；不自然具备实时预览 | 数月级探索，性能、供电、写卡一致性均未知 |
| Mac 监控导入目录并自动套 LUT | 常规软件原型可行性高 | 电脑收到照片后自动生成调色副本 | 约 2–5 天完成本地目录原型；自动联机传输另行验证；不能算机内直出 |

优先研究第一条。仅绕过“照片模式不能选 PPLUT”的菜单限制，可能完全不改变 JPEG 输出；照片链路也可能没有初始化所需硬件、缓冲或色彩转换，届时需要比菜单补丁大得多的工作。

色彩处理是另一道门槛。必须确认 LUT 所期待的输入编码和色域、照片链路中的实际数据、应用顺序以及输出编码。针对 S-Log3 的 LUT 不能未经转换直接当作 sRGB JPEG 滤镜；先得到“看起来有变化”的图片不足以证明色彩正确。

## 5. 分阶段开发门槛

### 阶段 A：离线调查，5–10 个有效工作日

使用合法取得的分析材料，沿用户 LUT 导入、PPLUT 选择和图像处理调用向下追踪，同时定位 JPEG 照片处理入口。现有源码只提供研究起点，本轮没有完成这些定位。

交付物是调用关系与数据格式证据，至少回答：

- LUT 是否由 AP 配置后交给 CP/图像处理器，还是走独立视频模块？
- 实时取景、视频编码和完整照片是否共享可调用的 LUT 处理环节？
- 照片输出所需缓冲、格式和生命周期是否适配？
- 不同白平衡/伽马下的输入输出色彩空间如何保证？

若只能找到 UI 检查而不能证明像素路径，结论为“尚不能开发可靠直出”，停止扩大实现承诺。若证据支持共享处理，再设计实验补丁。

### 阶段 B：建立机外参考，约 2–5 天，可独立进行

使用自制或明确授权 LUT，建立有界 `.cube` 解析和参考处理流程。以恒等表、通道映射表、灰阶和色块检查采样顺序、插值及编码转换；明确拒绝超限、截断、非有限数值和不支持的组合格式。输出仅写新文件，保留原始照片。

这一步提供机内结果的对照，不能证明机内接口存在。默认目录处理即可，不必为此进入 USB 服务模式。

### 阶段 C：机内实验原型，取决于阶段 A

先在可控实验设备上验证单 LUT、单张 JPEG。临时内存实验也有进程崩溃、拍摄异常和数据丢失风险，不能称为无风险；持久化还需另行验证。若接口与输入不明，不用逐个猜偏移的方式试写。

达到以下条件才考虑长期使用：

1. JPEG 全尺寸像素与机外参考相符，误差阈值按色彩空间和编码精度事先确定，包含灰阶、肤色、饱和色和高光。
2. 取景、JPEG、缩略图及回放一致；RAW 的影像数据、曝光和元数据影响分别检查。
3. 关机、冷启动、切换照片/视频及断开电脑后行为正确；测量拍摄延迟、写卡、温度和功耗。
4. 对支持模式完成回归，并明确不支持模式的拒绝/禁用行为；失败停止不冒充回滚完成。
5. 对该 LUT 补丁实际验证恢复路径；不沿用 FL2/FL3 的恢复承诺。

## 6. 专利传闻与个人使用

### 查到什么，没查到什么

松下确有相关专利。例如 [US12407915B2](https://patents.google.com/patent/US12407915B2/en) 的独立权利要求涉及保存并关联两组处理参数的选择信息，以及先按第一组处理、再按第二组转换颜色的装置结构。保护范围需要阅读具体权利要求，不能把它概括成“所有静态照片 LUT 都被独占”。

另一项 [US12739496B2 的 USPTO 授权公告](https://patentsgazette.uspto.gov/week37/OG/html/1550-3/US12739496-20260915.html)显示，权利要求 1 涉及用户指定两份 LUT，并在实时取景中应用它们的组合。它是另一种具体方案，也不能据此断言单 LUT 实现必然不侵权。

本轮**没有取得 Sony 因这些专利而限制 A7C II 照片 LUT 的官方证据**，也没有完成中国同族专利、其他相关专利、有效状态及拟实现方案的逐项比对。上述美国公开文本只用于确认存在相关技术权利要求，不能直接给中国境内使用下结论；Google Patents 的状态标记也不是法律有效性证明。

### 对“只用于学习和个人使用”的实际判断

以下按中国境内、纯个人且非生产经营的使用前提讨论：

- 《专利法》第十一条将相关禁止实施行为与生产经营目的联系起来，个人非经营研究/使用与商业开发应分别分析。
- 第七十五条第（四）项对“专为科学研究和实验”使用有关专利规定例外。技术验证可能需要考虑该条，但日常兴趣摄影不能只靠“学习用”标签自动归入例外。
- 是否收费不是唯一判断标准；公开分发、代刷、为产品开发测试或商业使用，不能自动沿用纯个人场景的结论。
- 第六十四条以权利要求确定保护范围。自己重新写代码、不用某个商品名称或改变 UI，并不自动排除专利问题。

依据：[国家知识产权局公布的《中华人民共和国专利法》（2020 年修正）第十一、六十四、七十五条](https://www.cnipa.gov.cn/art/2020/11/23/art_97_155167.html)。这是一般边界说明，尚未形成针对本方案的不侵权意见。

因此，你的用途支持继续进行个人技术研究，**无需仅因未经证实的专利传闻放弃可行性调查**；但“个人使用”不是对全部地区、发布方式和具体技术方案的通行豁免。后续若改变为公开发布或商业用途，需要根据完成后的实现重新评估。

代码许可、固件权利和 LUT 资产授权也分别存在。当前 [NOTICE.md](../NOTICE.md)明确 MIT 许可不宣称覆盖 Sony 固件衍生数据；实验使用自制或获授权 LUT，不把第三方收费 LUT、完整固件或机身备份随项目分发。
