# N3：旧演练目录的只读检查

第四十五轮新增 [captureinspect](../lutphoto/captureinspect.py)，检查[主机演练](CAPTURE-HOST-OFFLINE.md)、[会话演练](CAPTURE-SESSION-OFFLINE.md)或第四十七轮[原始认证/材料演练](CAPTURE-PIPELINE-OFFLINE.md)生成的一个明确目录。**只判断现存证据是否一致，不操作相机，不恢复、补写或续跑。** 不需要源码归档、相机、sudo、Docker 或原生共享库；没有目录搜索、任意文件读取、策略覆盖或设备入口。

本轮只检查新建的自制临时材料，没有读取用户私人备份。已有私人目录必须由本人明确指定范围后才检查；旧 FL23 工作目录、日常卡文件副本及第三方工具目录不是这里支持的演练格式。

## 使用已有演练目录

例如已经按[主机演练说明](CAPTURE-HOST-OFFLINE.md)生成过 `unknown-program` 目录时：

```sh
.venv/bin/python -S -B -m lutphoto.captureinspect inspect \
  --directory "$HOME/Pictures/A7C2-capture-demo/unknown-program"
```

命令只向终端输出有限的私人 JSON，不创建结果文件或修改输入。该例为全零 AP 被固定策略拒绝后的目录，预期退出 **1**、`NEEDS_REVIEW_INCOMPLETE`，不是相机备份成功。目录不存在就拒绝，不会自动创建；检查结束也不允许直接重跑原演练到同一目录。

| classification | 含义 | 退出码 |
| --- | --- | --- |
| `CONSISTENT_SIMULATION_COMPLETE` | 已识别演练格式，日志、确认顺序、必需材料及模型报告符合一致性条件 | 0 |
| `NEEDS_REVIEW_INCOMPLETE` | 已知演练未完成、缺报告/部分元数据或目录尚未初始化完整；没有足够证据证明完成 | 1 |
| `NEEDS_REVIEW_UNKNOWN` | 有未确认 INTENT，或演练明确报告未知；不推断仍可退出/重试 | 1 |
| `EVIDENCE_INCONSISTENT` | 发现链、哈希、文件清单、完成声明或流程标记等矛盾 | 1 |
| `REFUSED` | 活跃作业、不安全/不可读路径、权限/链接、大小上限或读取期间变化，不能可靠检查 | 1 |

命令参数错误仍使用标准退出码 2。证据不一致不等于已经证明有人篡改，也可能来自失败发布、遗失文件或其他中断。所有非完整分类均保留原件，不删除目录、不手改状态、不自动重试。

## 只读边界与核验内容

- 只沿显式目录的父链打开目录句柄，不解析链接来绕过拒绝；要求私人 POSIX 权限/本人所有、普通单链接文件。现有 `session.lock` 必须为空；以只读方式申请共享非阻塞 flock，活跃写入者持有排他锁时拒绝。**不创建锁文件，不打开 `/var/run` 系统相机锁**。
- 固定四个子目录，仅枚举有限条目；未知普通文件只检查类型/权限并报告异常，不读取内容、不反射名称。拒绝链接、FIFO、硬链接、陌生子目录、共享权限和超限条目。
- 流式 SHA/长度检查已知材料；单程序最多 128 MiB、快照 32 MiB、资源 1 MiB、事件 16 KiB、报告 128 KiB，总读取最多 512 MiB、总期限 1200 秒。事件最多 2048，来源目录最多 80 条，根目录最多 8 条；先检查文件及剩余额度，再读取，每块最多 64 KiB。
- JSON 拒绝重复键、非有限数与过深结构；检查事件名/字段、连续编号、前项 SHA、INTENT/ACK、材料记录和三种报告格式。目录/文件/锁 inode、大小、权限、修改/状态时间和目录项在读取结束再次核对，任何变化拒绝。
- 完成条件还要求精确的 ACK 顺序、原有 6 项或扩展 74 项材料、报告/日志/实际 SHA 一致、首末观察/退出标记、累计载荷及请求计数，没有未确认动作、待审阅或混合格式标记。报告不能把真实验证或写入标志升级为 true。

共享锁只约束遵守同一作业锁的进程，不证明设备闲置；目录最终复核也不是原子快照。文件读取和目录枚举可能更新访问时间 atime，本工具不承诺保存它；测试核对的是内容、目录项、权限、inode、mtime/ctime 不变。期限检查不能抢占正在阻塞的文件系统调用。

一个重要限制：主机同步或 ACK 持久化失败可能发生在完整响应之后。原演练进程即使曾知道通信结果，后来只读检查也无法从缺失的确认记录重建这一知识，所以仍保留未确认意图；不通过一份报告消除未知。报告缺失、部分事件、孤立材料和矛盾完成报告分别给出有限问题代码，不补写确认。

## 结果不能证明什么

JSON 只有分类、计数、有限问题代码和 false 边界，不复制输入路径、身份、程序/表/设置字节、原始异常、材料哈希或私人报告字段。结果仍为 `private_report:true`，应留在私人位置，不上传仓库。

哈希链不是签名，拥有目录写权限的人可以重写整套一致证据。`CONSISTENT_SIMULATION_COMPLETE` 只表示本次读取符合已知演练结构，不证明实际执行、真实机身、原厂程序策略、BK4/UXC 格式、捕获新鲜度、芯片角色、独立介质、恢复或写入资格。`program_policy_revalidated`、`material_formats_revalidated`、机身/角色/新鲜度等已列验证标志以及 `resume_allowed` 均为 false；没有重新执行原演练，也不替代[程序身份](PROGRAM-IDENTITY.md)和[材料检查](IMPORT-MATERIALS.md)。

固定 QAQLeonard/ma1co 署名及许可沿用，旧安装器、指纹、偏移、锁、测试、依赖和默认单份备份不变。检查器的固定守卫名另外与既有固定源码清单核对，运行 CLI 本身不加载归档或设备模块。
