## 本轮固定结果

- 可选 `requirements-custom-host.txt` 固定 Zig 0.13.0/pyelftools 0.32，位于忽略的 `research/materials/n3-host/env`；主环境未装 Zig。版本来自核验过的固定上游设备依赖文件，不替换旧运行依赖。
- `lutphoto.customhost` 在实际 macOS 27.0.1/arm64 上通过 Clang 21 的 AArch64 对象及 Zig 0.13.0 中性共享 ELF 探针；Zig 输出 1,720 字节、含 DT_INIT、无外部依赖/动态未定义符号。真实 worker 构建/ABI及 Keystone 问题仍未验证或解决。
- `lutphoto.custommigration` 的 S0–S3 是固定合成来源，只有 128 字节占位组件；完整 AP/CP 身份拒绝混合来源，固定五组件来源/目标 SHA、双模拟备份、精确逆向，保留未选字段并拒绝无关未保存设置。
- 意图后未知结果进入 NEEDS_REVIEW，禁止重放/自动恢复，即使完整哈希已是目标也不放行。日志只在内存，存储 token 不能证明实际介质独立；恢复示例只从计算出的合成目标开始，不消费未知现场。
- 新增 23 项专项，完整研究 190、Mac 39、旧上游 8，合计 237 项通过；包含 200 组故障矩阵。固定源码包/26 文件及旧 46 文件审计再次通过；实际 CLI 和探针结果在忽略的 `research/output/custom-round32/`。
- 上轮公开提交为 `fb904bd20534cbfe737535f356e880bea34f749f`，其 GitHub CI 通过。本轮沿用源码/文档审核后提交 `lut-photo/main` 的流程，结果以 Git 历史、远端 main 和本轮最终报告核对；不向 origin 或公开仓库上传环境、素材/备份、原始日志或生成报告。
- 用户已说明可提供 Windows 11 惠普电脑/考虑 Docker；它们可作备用编译环境，尚未实测，不能代替机内执行。当前 Mac 足够且用户无需操作；后续真有环境/物理协助需要时再明确说明具体要求，见[N3 环境说明](../docs/CUSTOM-MAC-OFFLINE.md#docker-和-windows-11-可以做什么)。
