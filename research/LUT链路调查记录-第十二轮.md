# LUT 链路调查：寄存器字段消费与条件式句柄生产

日期：2026-10-18。接续[第十一轮](LUT链路调查记录-第十一轮.md)，仅分析已有官方原版 CP 2.01；完整指纹和环境见[当前交接](HANDOFF.md)。未执行固件、接触 USB 或生成机内补丁。

本轮确认模式字段进入下层控制位、地址初始化存在清零分支，以及捕获模块的一条句柄生产链。**硬件读写方向、捕获/LUT 的实际句柄身份、有效像素传输及照片 LUT 使能仍未确认，机内直出尚未实现。**

## 1. 模式字段进入控制位，方向语义仍未知

`0xaac3f6` 的七项循环调用 `0xaac9f8`，在间距 `0x44` 的结果行中写入：

- 行 `+0x08`：`(描述项编号 < 3) OR (传入参数 1 != 0)`，当前循环编号范围为 0–6。第 3 项只有在该参数为零时才得到零，不能忽略参数条件。
- 行 `+0x0f`：上游类型值 1–16 时为 3，类型 17 时为 4；这是描述格式值，尚未解释为具体像素格式。

`0x446e18` 的相关通道分支进入 `0xaaeaaa`。后者仅对行首启用字等于 1 的项调用 `0xa59526(端口, 行+8)`；检查成功后到 `0xa58836`。

`0xa58860` 用 BFI 将描述首字节的低两位插入控制字的位 1–2，随后写入映射寄存器基址 `+0`。读回函数 `0xa58998` 在 `0xa589bc` 用 UBFX 从相同位置取回该字段。因此，编码位置和往返关系已连接；**没有独立依据把 0/1 命名为读/写或输入/输出**。

## 2. 候选地址并非总被写入活动地址寄存器

上一轮连接的候选编码双字位于行 `+0x10/+0x14`，传给上述驱动时分别成为描述 `+8/+0xc`。本轮发现 `0xa58836` 的两种行为：

| 描述格式值 | 映射寄存器 `+0x20` | 映射寄存器 `+0x18` |
| --- | --- | --- |
| 3 或 4 | 0 | 0 |
| 其他字节值 | 行 `+0x10` | 行 `+0x14` |

格式 3/4 分支在 `0xa58940` 将寄存器 `r1` 置零，两次存储均使用此零值。另一个写到映射寄存器 `+0x24` 的字来自行 `+0x18`，不能误当成候选双字的低字。

随后 `0xa59730 → 0xa58b50` 写的是映射基址 `+0x28` 到 `+0x44` 的另一组字段，不会在这个写入函数内直接恢复 `+0x20/+0x18`。其他地址更新函数、队列、内部通道连通及后续调用尚未全面追踪；**清零不证明候选字段永久无效，同样不能由此前的复制和计算就宣称成功输出像素**。

端口函数 `0x446f64` 按通道选择分支。对第 3 号描述项，映射结果为：

| 通道循环值 | 端口编号 | 静态表中的寄存器基址 |
| --- | --- | --- |
| 0 | `0x5a` | `0xf4000380` |
| 1 | `0x6e` | `0xf4100380` |
| 2 | `0x82` | `0xf4200380` |
| 3 | `0x96` | `0xf4300380` |

映射表链接地址 `0x1113fb8`，每项 12 字节，取项内 `+4`。仅核对这四项，不假定整张表长度；这些地址来自静态代码/数据，没有进行硬件寄存器访问。

## 3. 捕获句柄的一条生产链

初始化代码把选定模块的虚表设为链接地址 `0xe769dc`，虚表 `+8` 的 Thumb 指针指向文件偏移 `0x3791dc`。

基础打开函数 `0xa0a036` 在模块 `+0x28 == 0` 的新打开分支，把模块 `+0x24` 的地址作为句柄输出指针传入该虚函数。配置 `+8 == 0` 时，`0x379228 → 0x44505c` 将模块 `+0x12c` 的选择值交给 `0x445168`，再调用 `0x4452d4` 生成并发布句柄。配置值为 1 的另一路是 `0xaaaa78`，本轮未展开其内部。

已核对的选择值 3–9 到逻辑路由表为 `[0, 1, 2, 3, 5, 6, 4]`。选定模块的初始值 9 对应路由 4，但必须满足相关分支、锁检查成功及四项注册表类型字全部为零；任一类型字非零进入忙状态 3，不绕过检查。初始值及此条件关系不能代替运行时选择验证。

发布器 `0x4452d4` 按路由选择注册表中的种子槽 `[0,1,2,3,0,0,2]`，计算 `low16(原句柄+1) | (路由<<16)`；参数为零才另加最高位，本打开调用传 1。类型参数 0 对应发布类型字 1。路由 4 将同一句柄和类型字写到注册表 `0x1a7e578` 的四项。

捕获传输包装函数在 `0x379072` 读取模块 `+0x24`，通过局部指针交给 `0x4459c8`。这连接了**条件式生产和该字段的取用**，并未验证照片拍摄时打开路径的实际执行、后续重用、释放、改写或异步顺序。

## 4. LUT 提交来自另一上下文字段

回调 `0xa234c2` 从自己的上下文 `+0x13b4` 读取句柄，以 `+0x13b8` 为 LUT 参数传入 `0x3e076c`。分发器先把句柄值存入局部 `+0x30`，再于 `0x3e087c` 将该局部变量的指针传给 User3D `0x44615c`。

这个上下文 `+0x13b4` 的赋值生产者尚未连接到捕获模块 `+0x24`。共用上一轮的解析器和注册表，仍不足以证明同一句柄、同一时刻、最终通道或照片 LUT 使能；不能将旁边的 LUT 参数或全局计数当作句柄来源。
