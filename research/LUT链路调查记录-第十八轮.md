### 释放清缓存与其他第 28 位写入者

`0xaa8a02` 按通道将 `0x1a7e538` 等三组软件数组的对应字清零，本函数没有 MMIO 写入。包装器 `0x446de0` 按七路范围选择通道，TBB 数据/填充 `[0x446df0,0x446df8)` 与代码分开并核对所有目标。两条已知句柄释放路径于 `0xaaa298`、`0xaab244` 调用它，之前已有类型清除及其他清理调用。**不能把该缓存归零当作硬件位已归零，也不能把整个释放视为事务回滚。**

条件式入口 `0xaac28c` 在输入种类等于 2 时，经 `0xaaea56 → 0xaa97dc` 将固定控制字 `0x10100169` 同时写入通道块 `+0x1100` 和缓存。该初值的第 28 位本来就是 1。因此，“缓存位为 1”本身不能证明 User3D 已运行或照片 LUT 已使能。种类的业务名称及真实运行选择未证。

整字写入器 `0xaa8b3e` 从零构造控制字，从参数 `+0x68` 取低 1 位写入第 28 位，再写寄存器和缓存。另一流程在 `0xaabbea` 读取缓存第 28 位并归一为 0/1，存本地结构 `+0x2cc`，经 `0xaaea40 → 0xaa8a2a → 0xaa8b3e` 回填：完整参数 `+0x264` 子结构再加 `+0x68`，恰为 `+0x2cc`。这是选定字段连接，被调函数、别名和并发的全部副作用未证。多种写入方式并存，不能只围绕一次 User3D 置位推断生命周期。

### 原生准备入口及三条清零条件

原生调度 `0x3e076c` 在前置检查通过后，读取状态字 `0x1a6aefc`；不等于 1 时，`0x3e081a` 调准备入口 `0xaaabca`。准备返回 0 后，所查分支将状态设为 1。这里仅记录数值条件，不命名拍摄模式。

准备入口解析句柄路由和上下文，调用 `0xaaadd6` 检查所选通道的缓存第 21 位。另一检查 `0xaaae22 → 0xaac36a → 0xaaa074` 读取通道 `+0x10fc` 的位 `[1:0]`、位 4、8、12：所有选中通道的四字段均非零时返回 0，某通道不满足则返回 8。硬件状态含义未知，不能称为“空闲”或“完成”。

前置解析与范围取得成功时，至少有以下三条潜在路径汇入 `0xaaad64 → 0xaac34a`，清第 28 位：

| 缓存第 21 位检查 | 后续原始条件 | 汇入方式 |
| --- | --- | --- |
| 返回 0 | 通道状态检查非零 | 直接到范围/清零循环 |
| 返回 0 | 通道状态检查为 0，且 `0xa70b0a`、`0xa70990` 依次返回 0 | 经控制调用汇入 |
| 返回 8 | 先逐通道构造第 21 位为 1，且 `0xa70794` 返回 0 | 经另一分支汇入 |

清零并非只由“通道状态检查非零”控制。工具复用保守潜在路径模型，为三条路径分别给定原始分支选择并核对可达。**路径存在不证明相机上的返回值、时序、终止、锁或硬件同步。** 清零后还有配置调用，并把输入句柄存到 `0x1a7e608`；这些接口的全部语义和效果尚未核对。准备过程不能代替异步配置队列完成或整帧同步证据，第 28 位功能名及极性仍未知。
