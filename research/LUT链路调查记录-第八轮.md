# LUT 链路调查：JPEG 初始字段与共享就绪条件

日期：2026-10-18。沿[第七轮](LUT链路调查记录-第七轮.md)继续分析同一官方原版 CP 2.01，完整指纹和材料来源见[首轮](LUT链路调查记录.md)。本轮只读，没有执行固件、运行相机命令或生成机内补丁。

本轮明确了主图 JPEG 输入/输出地址的参数来源，建立初始字段的稀疏数值模型，并把 LUT 提交、回调和 VFX 启动检查使用的共享就绪字段连接起来。**VFX 输出与主图 JPEG 输入的缓冲身份仍未连接，实际尺寸、像素格式和色彩条件也未确认。**

## 1. 主图 JPEG 的两个地址来自哪里

主图构造函数入口 `0x3859dc` 内的局部数据流：

| 项目 | 观察 |
| --- | --- |
| 第一个查询句柄 | 从对象 `+0x5afc` 读取，调用 `0xa13bb2`，结果写入 `sp+0x250` |
| 第二个查询句柄 | 从对象 `+0x5b18` 读取，同一查询函数，结果写入 `sp+0x178` |
| 第一个地址 | 取第一份结果 `+0x18` 的两个字，即 `sp+0x268`，写入前缀 `+0` |
| 第二个地址 | 取第二份结果 `+0x18` 的两个字，即 `sp+0x190`，写入前缀 `+8` |
| 六个 16 位字段 | 从对象 `+0x6088` 起复制 12 字节到前缀 `+0x10` |

查询包装 `0xa13bb2` 调用 `0x409858`；后者的成功处理段把 `0xd8`（216）字节回复复制到调用者的输出区。本轮只确认取值来源，不把回复中的地址当作已证明的物理映射或有效像素内存。

前缀随后作为 `0x385278` 的输入。该函数把前缀 `+0` 的 64 位值复制到初始参数 `+0`，把前缀 `+8` 的 64 位值复制到参数 `+0x30`。

此前待展开的可选函数 `0x39d764` 使用 `JPEG IN` / `JPEG OUT` 标签打印参数：前者读取参数首个双字，后者读取 `+0x30` 的双字。按这一标签及读取位置，将两者记为输入/输出地址。**该函数是参数日志入口，未见直接改写输入结构；不能把它当成像素转换器。** 地址角色是静态代码和日志标签的关联，尚无运行内存或图像验证。

## 2. 初始字段模型与未知位置

`0x385278` 的初始构造将六个 u16 扩展为 u32，并保留若干重复字段。偏移如下，均相对输入前缀/构造参数首地址：

| 来源 | 初始参数位置 | 操作 |
| --- | --- | --- |
| `+0`、`+8`，各 8 字节 | `+0`、`+0x30` | 保留完整双字 |
| `+0x10`、`+0x12` | `+8`、`+0xc` | u16 零扩展至 u32 |
| `+0x18`、`+0x1a` | `+0x10`、`+0x14` | u16 零扩展至 u32 |
| `+0x14`、`+0x16` | `+0x18/+0x1c`、`+0x28/+0x2c`、`+0x44/+0x48` | 同一对 u16 的多处副本 |
| `+0x1c`、`+0x20` | `+0x3c`、`+0x40` | 两个独立 u32 |
| 上述两个 u32 相加 | `+0x38` | 32 位 ADD，溢出按模 `2^32` 回绕，不是 64 位地址加法 |
| `+0x24`、`+0x28` | `+0x68`、`+0x6c` | 两个独立 u32，未擅自合并成一个地址 |

模型只接受恰好 44 字节的前缀，返回已知字段的宽度和整数值，不输出二进制设备参数。不能仅凭字段排列就为六个 u16 指定完整的宽高、裁切或步长语义。

在初始 `0x78` 字节区间中，`+0x4c` 的一个字没有在该构造段赋值，模型保留为空缺。`+0x60/+0x64` 起初被清零，但 `0x38540c` 随后从输入的索引字段取值并覆盖它们。故初始模型不等于最终完整参数，不能用于直接上传。

## 3. VFX 一侧已追到的字段

VFX 传输函数 `0x3dfedc` 的首通道参数块位于其局部栈 `+0x978`。本轮确认：

- 首参数块 `+0x18` 来自“第六个参数所指的指针，再取该指针 `+8` 的一个字”，读取宽度为 4 字节。没有把相邻几何字段拼成一个未经证明的 64 位地址。
- 第十个参数非零时，读取其首两个字，写到首参数块 `+0x160/+0x164`；这是**候选输出地址**，底层驱动角色仍待核对。
- 第七个参数的 `+2/+0` 两个 u16 分别写到块 `+0x1c/+0x168`，其具体尺寸含义和实际值仍未确认。

这里从 `r0` 为第一个参数开始计数。函数序言给出 `r7 = 入口 SP - 8`；上述参数分别由 `[r7+0xc]`、`[r7+0x1c]`、`[r7+0x10]` 读取，报告也记录入口栈偏移，避免混用从零开始的下标。

这些字段给出了继续向调用者追踪的位置，但没有证据把候选输出与上一节的 JPEG 输入句柄视为同一缓冲。像素参数也不能与 LUT 表地址混为一谈。

## 4. LUT 提交、回调与 VFX 使用同一组就绪字段

新连接的三个代码段：

| 阶段 | CP 文件偏移 | 字段行为 |
| --- | --- | --- |
| LUT 分发器准备提交 | `0x3e07c0–0x3e07d0` | 在相应状态分支中，将链接地址 `0x1b1e235` 的字节置 1，将 `0x1a6aefc` 的状态字置 2 |
| 交给用户 LUT 接口的回调 | `0x3e0812` / `0x3e087c` | ArtGen 与 User3D 分支均传入 Thumb 回调 `0x3e09f0` |
| 回调本体 | `0x3e09f0` | 先清零该字节；结果参数非零时还将同一个状态字清零 |
| VFX 启动的初始检查 | `0x3dff06–0x3dff28` | 读取同一状态字和字节，要求状态为 2 且字节为 0；后续还有开关和等待分支 |

接口立即返回错误时，分发器也会清零状态和字节。根据字段读写与回调参数，把该字节称为“等待回调”标志；不是凭日志名称猜测。

这补齐了“提交后的等待标志 → 回调清除 → 传输检查”的静态连接。**状态字为 2 本身不足以说明可使用 LUT。** 但共享字段也不证明所有任务的运行顺序、内存可见性、旧表释放或所有错误路径已正确同步，不能把它升级为完整跨队列时序证明。
