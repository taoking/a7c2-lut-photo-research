# LUT 链路调查：句柄生产者与捕获 VFX 路径

日期：2026-10-18。接续[第八轮](LUT链路调查记录-第八轮.md)，只读分析同一官方原版 CP 2.01。材料指纹见[当前交接](HANDOFF.md)。本轮没有执行固件、连接相机或生成机内补丁。

本轮找到 MAIN 所用槽位的赋值生产者，并定位另一条使用相同槽位偏移的捕获 VFX 参数路径。**这缩小了缓冲桥接的调查范围，尚未证明捕获 VFX 使用用户 LUT，也未证明它与 MAIN 使用同一时刻、同一实例的缓冲。** 总任务仍停留在[总计划](../plan.md)的 M3/M4。

## 1. `+0x5afc` 是可转移的角色槽

设置函数 `0xa05122` 使用 `对象 + 0x5ad8 + 4 × 角色编号` 计算槽位。编号 9 对应 `+0x5afc`，编号 10 对应 `+0x5b00`。MAIN 的第二个 JPEG 查询句柄在 `+0x5b18`，**不能把编号 10 直接命名为 JPEG 输出**。

`0x36c70c` 读取 `+0x5afc`，已有值不是 `0xffffffff` 时直接返回；需要获取句柄时，调用 `0x3a1940`，接收区从局部栈 `+8` 开始。返回码为 0 的分支从该区 `+0xc` 取一个字，在 `0x36c7d6` 写回 `+0x5afc`，并把伴随值写到对象 `+0x5f80`。本轮确认调用与写回，没有把 `0x3a1940` 的全部分支或参数枚举当作已解释的分配器契约。

槽位会变化，不能把它当成永久缓冲地址：

| 局部代码 | 观察 |
| --- | --- |
| `0x37efb0` 起 | 把工作对象 `+0x5afc` 的句柄放到另一对象 `+0x52f0`，随后将源槽置 `0xffffffff` |
| `0x37f0ec` 起 | 通过设置函数把旧编号 9 转到编号 10，清空编号 9；再把另一对象 `+0x52f0` 放回编号 9，并清空另一源槽 |

这里证明的是局部读写与失效，不证明两个对象的真实身份、转移发生的时刻、引用计数或底层释放已完成。

## 2. 另一条捕获 VFX 路径查询同一槽位偏移

带 `Stage_Dev_Vfx` 日志的阶段入口为 `0x3816c4`。它先在 `0x38171e` 调用上述句柄生产者，再以同一工作指针和标志 `0x2b` 调用 `0x3818b8`。

后者在标志 `0x20` 分支中，于 `0x381a3a` 查询工作对象 `+0x5afc`，回复区位于配置首地址 `+0xd8`。沿用上一轮查到的回复 `+0x18` 双字位置，候选地址位于配置 `+0xf0`。

随后调用 `0x382bd8`，又把同一局部配置首地址作为第 4 个参数交给 `0x384354`。后者的 `0x384434` 确实从该参数 `+0xf0` 读取两个字。**中间调用对配置和状态的全部影响尚未审计；本轮记录相同区域与读取位置，不把查询值未经改写地贯穿全程当作已证事实。**

这条捕获路径与上一轮 `0x3dfedc` 的路径使用不同的上层构造/包装函数，不能把后者已找到的 LUT 就绪检查直接搬到前者。

## 3. 换算后的候选字段与上一轮一致

`0x384354` 的相关条件是标志包含 `0x20`，且工作对象 `+0x65b4` 不等于 1。满足后：

1. 读取配置 `+0xf0` 的低/高两个字，暂存在栈上时交换顺序。
2. 在通道构造区 `+0x170/+0x174` 分别写入低/高字，最终顺序与原双字一致。
3. 传给包装函数的通道指针是构造区 `+0x10`；因此从驱动所收通道指针看，字段是 `+0x160/+0x164`。

这与上一轮 VFX 候选输出双字的偏移一致。捕获包装函数为 `0x378f28`，在 `0x379080` 调用同一 VFX API `0x4459c8`。底层尚未核实，故继续称“候选地址”，不把字段相同升级为输出角色、有效像素内存或成功传输。

工作对象 `+0x65b4 == 1` 时会跳过上述两个字的写入，不能宣称各模式都会填充地址。通道构造步长是 `0x320`，请求组步长是 `0xc90`，本轮没有把它们命名为像素行步长或图像尺寸。

## 4. 有界选择表，不把数据当代码

包装函数检查模块字段 `+0x12c`，以其值减 3 索引七项 TBB 表。表数据在 `[0x378ffc, 0x379003)`，下一字节为对齐填充；两者均从代码解码区间排除。确认的目标及首个构造通道传入的 API 参数如下：

| 选择值 | 分支文件偏移 | 首通道所在 API 参数（r0 为第 1 项） |
| --- | --- | --- |
| 3 | `0x379004` | 2 |
| 4 | `0x379072` | 3 |
| 5 | `0x379042` | 4 |
| 6 | `0x37904a` | 5，即入口栈 `+0` |
| 7 | `0x379054` | 2 |
| 8 | `0x379060` | 4 |
| 9 | `0x37906a` | 2 |

这些是内部选择值，尚未映射到相机拍摄模式。TBB 目标由表基址加无符号表项的两倍得出，仍逐一核对目标落在已解码代码中；不宣称完整控制流图或条件必然可达。
