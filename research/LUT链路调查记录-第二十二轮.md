### 发送对象、注册描述与有界操作分发

发送包装 `0x409858` 把域值 `0x61003c` 和长度 `0xd8` 交给构造函数 `0x530176`；构造的对象 `+8` 保存域值。实际发送从对象 `+8` 取域值、从对象 `+0` 取消息指针，经 `0xae401c → 0x45cd60`。

注册调用 `0x495dc4 → 0x45c8f8` 使用相同域值，传入 Thumb 回调 `0xb1620a`。公共描述的适配函数 `0xae3c34` 从描述 `+0x14` 取回调并间接调用；查询回调读取消息容量和关联值，再调用 `0xb13df6`。这里只连接选定注册/发送字段与调用，不把静态存在当成初始化成功、运行送达或完整同步证明，也未穷举被调函数/别名的全部副作用。

分发器将请求的前 `min(容量,0x28)` 字节复制到内部记录 `+0xc`。操作半字小于 `0x2e` 时，按操作值索引位于链接地址 `0xea64bc` 的 u32 函数表；选中项 `0x2a` 指向 `0xb13764`。脚本检查表边界和该 Thumb 目标，不输出完整函数表。

### 更正：0x55 是回显标识

处理函数读取内部记录 `+0x20`，将其写到回复 `+6`。由于原请求从内部记录 `+0xc` 开始，这一来源就是请求 `+0x14`，在当前查询中值为 `0x55`。回复头则由请求操作值按位或 `0x8000` 得到，即 `0x802a`。

因此，前轮把 `0x55` 称作“命令”不准确：实际分发操作是 `0x2a`，`0x55` 是请求字段的回显标识。本轮已在前轮记录和研究说明补充更正。旧 JSON 的 command 字段名保留兼容和原报告复核，其数值不变；新报告采用 tag 字段，不把它再当一层操作分发。

### 句柄如何得到回复地址对

处理函数 `0xb13764` 将请求句柄和选项 `0x1001` 交给 `0xb16a52`，输出地址记录从回复 `+0x18` 开始，计数写回复半字 `+8`。

| 位置 | 所查用途/原始条件 |
| --- | --- |
| 输入句柄低 16 位中的位 0–9 | 单元槽索引，排除 `0x3ff` |
| 句柄位 10–14 | 与单元记录 `+0xb` 的字节比较；业务命名及代号更新规则未证 |
| `*[0x1a8c558] + (槽索引<<6)` | 选定单元记录，步长 `0x40` |
| 单元记录半字 `+0xc` | 选项 `0x1001` 的可填充分支接受原始状态 1、2、3 |
| 单元记录半字 `+0xe` | 循环记录数，同时写回复计数 |
| 单元记录 `+0x10` 起的指针数组 | 每项 4 字节，指向一条描述 |
| 描述双字 `+8` 与 u32 `+0x10` | 64 位基值加 32 位偏移，带进位写回复中的地址对 |
| 描述 u32 `+0x14` | 写入该回复记录 `+8`，不在本轮命名其完整尺寸/格式含义 |

每条回复记录步长 `0x10`。所查加法为低字 `ADDS` 加偏移、高字 `ADC` 取进位，并非直接把某个描述指针当作像素地址。**这些字段来自运行单元表；基值、偏移、表/描述分配和复用、地址空间及真实像素都还未验证。**

这个单元句柄的局部解析不能套用到原生 VFX 注册句柄的位 31。两套解析及 API 对应的运行身份仍未连接。地址填充后还调用 `0xb15bc2`，本轮没有穷举它、全局别名及其他调用的副作用，也不宣称整条查询在机内只读或具有完整事务保证；本轮执行的仅是电脑端只读分析。

### 回复复制长度的边界

`0x802a` 属于分发器选定的可变长度回复分支。计数在 1–12 时，选定长度为 `0x18+计数*0x10`，最大为 `0xd8`；不在该范围时选用 `0x28`。复制回原消息前，再取所选长度与调用者消息容量的较小值。

这里的 12 来自回复复制策略，**不是已证明的单元记录容量或地址填充循环的计数上界**。本轮只读取指令和选定静态表项，不跟随运行指针或生成完整消息。P3 已从“未知回复生产者”推进到“单元记录/描述字段来源”；捕获与 MAIN 是否查询同一实例、是否发生复用、LUT 输出是否就是该缓冲，仍未闭合。
