### 配置指针生产与入口条件差异

`0x37dd28` 从阶段取工作对象，调用 `0x37df00` 选择索引，将索引写到工作 `+0x5a98`，再从固定指针表 `0x110f2ec` 读取并写入工作 `+0x5a9c`。选中空指针的可见分支回退到表项 0。索引的全部范围与所有配置写入者尚未穷举。

本轮检查表项 1–23 对应的 23 行静态配置，行步长 `0x30`；表项 0 指向外部运行位置 `0x1a50644`，不能当成已知静态行。检查范围不等于已证明的全部运行选择范围。

在所查静态行中，捕获原值/有效索引 2 仅出现在第 11 行，其组 11–15 字段为 `(2,0,2,0,0)`。该行 MAIN 原值是 0，**不满足此前 MAIN 主图入口所需的有效索引 1 或特殊原值 3**。两组条件在所查静态行中没有交集。

因此，前轮组 11→15 的条件式转换证据仍成立，但不能把捕获 `0x3816c4` 和 MAIN `0x3859dc` 的不同配置条件拼成已验证的同次拍摄像素链。这是对原有缺口的具体收窄，不是“机内 LUT 不可能”或“所有拍照路径都不存在”的结论；动态行、其他捕获索引及配置改写仍需核对。

### MAIN 步骤 0 的直接缓冲槽

`0x385d00` 从阶段 `+0` 取工作对象，向 `0x36c8a4` 请求下列角色，其中角色 20 的调用受条件控制。辅助函数先复用已有槽；需要分配时调用 `0x3a1940`，成功回复 `+0xc` 的句柄写回 `工作+0x5ad8+4*角色`。

| 调用顺序中的角色 | 所查直接工作槽 |
| --- | --- |
| 16 | `+0x5b18`，与此前 MAIN 输出查询槽相符 |
| 20，条件调用 | `+0x5b28` |
| 17 | `+0x5b1c` |

本辅助函数对这些角色的直接写槽不含角色 9 的 `+0x5afc`。这区分了 MAIN 前置缓冲与已知输入槽，不能据此宣称全部被调用函数没有间接副作用、输入缓冲生命周期完整或像素硬件处理已经完成。步骤 0 可见返回值为 0/5，其后仍受前轮执行器的步骤推进/清理分支控制。
