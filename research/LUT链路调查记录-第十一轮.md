# LUT 链路调查：下层地址消费与共用逻辑路由

日期：2026-10-18。接续[第十轮](LUT链路调查记录-第十轮.md)，只读同一官方原版 CP 2.01，完整材料指纹见[交接](HANDOFF.md)。未执行固件、连接相机或生成机内载荷/补丁。

本轮把候选双字的位置连到下层地址计算和传输描述项，并确认 VFX 传输与用户 LUT 上传共用逻辑路由解析器。**仍未确认硬件输出方向、实际句柄/通道对应、捕获照片的 LUT 使能，或到 MAIN JPEG 的完整缓冲身份。**

## 1. 候选双字进入两种下层描述结构

VFX API `0x4459c8` 按选定通道取参数指针，复制 `0x320` 字节到链接临时区 `0x2263360`。候选双字位于传入通道 `+0x160`，复制后仍为临时区 `+0x160`。

随后从临时区 `+0x158` 起复制 `0x70` 字节，两条字段布局如下：

| 目的结构 | 复制目的偏移 | 候选双字位置 | 被调函数使用的基址视图 | 双字相对该视图 |
| --- | --- | --- | --- | --- |
| 链接区 `0x2262cd8` | `+0x168` | `+0x170` | 结构 `+8` | `+0x168` |
| 链接区 `0x2263038` | `+0x160` | `+0x168` | 结构 `+0x10` | `+0x158` |

相同的 `+0x160/+0x168/+0x170` 在不同基址中含义不同，工具显式保留视图换算。这里连接的是已观察的字段复制位置；中间的 `0xaaa378/0xaaa758` 等调用与全部别名/缓存副作用并未全面验证，不能把布局连接当成运行值全程不变。

## 2. 从第 3 号描述项读取双字并计算地址

`0x445d52 → 0xaac3a2 → 0xaac3f6 → 0xaac7c6` 使用第一种结构的 `+8` 视图。

循环共有 7 项，编号从 0 开始，每项间距 `0x70`。第 3 项的 `+0x18` 恰是视图 `+0x168`，因此与上表候选双字的位置吻合。在描述项启用、类型检查等条件通过的分支，`0xaac7e6` 读取两个字；后续：

1. `0xaac9c2` 对低字执行带标志加法，加数来自若干 32 位运算结果逻辑右移 3 位。
2. 中间 LDR 不改条件标志，`0xaac9ca` 用 ADC 将低字进位加到高字；不能用单个 32 位地址代替。
3. `0x446950` 根据模式处理地址：非零模式保留双字；零模式查找四项区间映射。实际地址映射、几何字段含义及模式语义尚未验证。
4. `0xaac9da` 把结果写入间距 `0x44` 的传输描述行 `+0x10`；高字进一步编码成 `(规范化高字 << 8) & 0x300`。

故候选字段确实参与下层地址计算，不能把它当成普通长度字段；也不能要求最终编码地址与 JPEG 查询地址简单相等。**这仍未证明对应硬件的输入/输出方向、有效像素内存或成功处理。**

## 3. VFX 传输与用户 LUT 共用解析器

| 调用方 | 调用点 | 解析器 |
| --- | --- | --- |
| VFX 传输 `0x4459c8` | `0x4459ec` | `0x445788`，类型参数 0 |
| User3D `0x44615c` | `0x44618a / 0x44619c` | 同一解析器，先尝试类型 0，失败后尝试 1 |

解析器比较链接注册表 `0x1a7e578` 的四项记录，每项 8 字节，按句柄与类型匹配形成通道掩码。已核对映射：

| 通道掩码 | 逻辑路由 | 传输 API 的通道循环范围（含两端） |
| --- | --- | --- |
| `0x1` | 0 | 0–0 |
| `0x2` | 1 | 1–1 |
| `0x3` | 5 | 0–1 |
| `0x4` | 2 | 2–2 |
| `0x8` | 3 | 3–3 |
| `0xc` | 6 | 2–3 |
| `0xf` | 4 | 0–3 |

逻辑路由 4/5/6 与单个通道编号不能混用，也不能直接命名为拍摄模式。传输 API 会进一步拆成 0–3 的通道循环；User3D 经 `0xaac2da` 查询另一张七项表，原版表把逻辑值 0–6 分别映射为 0–6，后续传给 LUT 下层。

本轮确认共用逻辑解析器，**没有确认上层捕获模块与 LUT 上传实际提交的是同一句柄、同一时刻或最终硬件通道**。这些是下一轮需要继续连接的关系，共用解析器本身不证明照片 LUT 已启用。
