### 准备后的六组配置目标

准备入口的三个本地参数块 `+0x48/+0x30/+0x10` 分别初始清零 `0x14/0x18/0x1c` 字节，另传一个标量 0。清第 28 位后，按下表顺序调用六个接口。原生初始绑定将模板复制到表 `0x1a78d18`，表项步长 `0x90`，其中描述大小 `0x8c`；核对 ID、模板、目标位置与复制调用后，只读取选中模板的偏移数组。

| 准备后接口 | 描述 ID | 相对逻辑配置基址的目标偏移 |
| --- | --- | --- |
| `0xa70fda` | 3 | `0x100/0x110` |
| `0xa7105e` | 4 | `0x140/0x150` |
| `0xa710e2` | 5 | `0x180/0x190` |
| `0xa713f0` | 11 | `0x340` |
| `0xa714f4` | 13 | `0x400/0x410/0x414` |
| `0xa71472` | 12 | `0x380/0x390/0x3b0` |

这些成功分支最终经 `0xa7aa0c → 0xa6fff8 → 0xa6ffe4` 直接访问配置寄存器。最后一级写入、读回记录并执行 DSB，没有比较读回值，不能把接口返回 0 作为硬件成功验证。初始零值也不证明全部中间副作用、别名或并发保持源内存，描述表实际初始化和运行内容未证。

ID 13 的三个偏移与后续 User3D 六字配置相同，但准备阶段的参数结构初始为零。ID 12 的 `+0x380` 属于逻辑配置基址 `0xf4009000+(上下文<<20)`；捕获传输端口基址则为 `0xf4000380` 等，**不能仅凭相同偏移把两者接成像素链**。

### 完整句柄比较与完成回调

User3D 在 `0x446230` 将输入句柄与准备时保存的 `0x1a7e608` 做完整 32 位相等比较，所查比较块没有屏蔽位 31。这里只证明该比较保留该位，未解释位 31 的业务含义，也未证明跨调用的实际句柄身份。

原生调用 `0x3e087c` 传入回调 `0x3e09f0`，经此前已核对的配置描述和公共异步处理连接到控制器回调 `0xa7b1f8`。下层输入为 0 时给上层参数 0，非零时给上层 -6；调用上层后再发完成信号。实际运行执行仍未验证。

| 位置/条件 | 所查直接可见存储 |
| --- | --- |
| 原生调度进入配置提交 | 忙字节 `0x1b1e235=1`，状态字 `0x1a6aefc=2` |
| 上层回调，任意参数 | 忙字节清 0 |
| 上层回调，参数非零 | 状态字清 0，并清 `0x1a6af00` 保存的选定参数字 |
| 上层回调，参数为零 | 回调自身不写状态字；不能据此穷举其他写者 |

`0x1a6af00` 在此保存的是配置输入中的选定参数字，不将其命名为原生句柄。成功回调清忙不代表照片整帧完成，也不补齐 User3D 排队返回后的通道置位、回调和其他任务之间的全部同步。缓存、锁、运行顺序、MAIN 身份及真实像素仍缺证据。
