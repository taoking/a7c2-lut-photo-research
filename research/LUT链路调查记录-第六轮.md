# LUT 链路调查：快照刷新与回调提交

日期：2026-10-18。沿[第五轮](LUT链路调查记录-第五轮.md)继续分析相同的官方原版 CP 2.01；材料及指纹见[首轮记录](LUT链路调查记录.md)。本轮只读分析，没有执行固件或操作相机。

新增结论：初始构造之外，存在向同一个参数根复制内部状态的调用；它位于带 `VD_Pre S` 日志的回调中。另一个排队回调可调用已定位的 LUT 分发器。这补齐了刷新入口和回调描述符提交的静态证据，**仍未证明实际刷新频率、照片模式或完整分辨率 JPEG 像素处理**。

## 1. 初始构造之外的快照复制

第五轮确认的初始复制由构造函数 `0xa26140` 完成。本轮找到另一条路径：

| 步骤 | CP 文件偏移 | 静态观察 |
| --- | --- | --- |
| 回调入口 | `0x3cf484` | `0x3cf4a8` 的 PC 相对地址指向 `VD_Pre S` 日志 |
| 取得目标根 | `0x3cf9e6–0x3cf9ee` | MOVW/MOVT 得到链接地址 `0x172fe50`，保存在 `r4` |
| 传递目标 | `0x3cfa32–0x3cfa68` | `r5 = r4`，随后以 `r0 = r5` 调用 `0x7d2d54` |
| 复制辅助函数 | `0x7d2d54` | 保存传入目标，取得链接地址 `0x165a720` 作为源，长度 `0xd64` |
| 执行复制的调用 | `0x7d2d74` | 调用此前确认的 ARM 复制入口 `0x51660c` |

源、目标、长度都与第五轮初始快照相同。表/寄存器地址、两段长度和更新计数都在这 3428 字节之内，因此字段位置可继续连接到第四轮的 96 字节复制和 VFX 输入结构。这里证明的是复制调用和参数来源，不能保证任何一次相机操作都会抵达它。

复制前调用 `0x4da5a0(0x26)`；仅返回零时进行复制，之后调用 `0x4d9f58(0x26)`。非零返回会跳过复制及后一个调用。这是成对控制 API 的代码证据，**尚未将其完整识别为某类锁，也未确认写入者使用同样的同步机制**。不能据此宣称并发安全或 LUT 缓冲生命周期已解决。

工具检查根地址在局部窗口中的显式寄存器传递；跨调用按 ABI 的被调用者保存寄存器规则解释，未做完整内存副作用分析。

## 2. 回调描述符如何提交

进一步展开辅助函数后，这里的证据更准确地表述为“提交回调描述符”，而不是已经证明所有回调的长期注册和调度。

| 路径 | 描述符与提交点 | 辅助函数中的证据 |
| --- | --- | --- |
| `VD_Pre` | `0x3cef9a/0x3cefae` 重建 Thumb 指针，指向 `0x3cf484`；写到栈描述符 `+8`，在 `0x3cefc0` 提交 | `0x407f1c` 复制描述符的 5 个字，加上两个参数字，以 28 字节缓冲调用下一层 API |
| VFX 消费 | `0x3bef6c/0x3bef80` 重建 Thumb 指针，指向 `0xa234c2`；写到另一描述符 `+8`，在 `0x3bef8a` 提交 | `0xa20c16` 整理描述符及参数，调用 `0xa214e2`；后者复制 32 字节到节点，连接链表并增加计数 |

VFX 回调 `0xa234c2` 从对象 `+0x13b4` 读取句柄，把对象 `+0x13b8` 作为输入，在 `0xa234d4` 调用已确认的 `0x3e076c` LUT 分发器。该分发器中的选择值 10 分支可抵达 User3D/User3DArtGen，详见[第二轮](LUT链路调查记录-第二轮.md)和[第四轮](LUT链路调查记录-第四轮.md)。

本轮没有把两个提交点当作完整运行调用图：队列/链表消费者、回调执行次数、错误与取消处理、模式分派还没有全部展开。`VD_Pre` 名称提供调度线索，但不能仅按名字认定每帧执行，更不能认定作用于静态照片。

## 3. LUT 未就绪时，传输可以继续

函数 `0x3dfedc` 中存在带 `StartVfx: MLUT not ready` 日志的分支：

- 初始检查要求链接地址 `0x1a6aefc` 的状态字为 2，并要求 `0x1b1e235` 的字节为 0。随后还有开关及等待状态的分支；这两个条件并不是全部运行条件。
- 未满足初始检查时，可进入 `0x3dff7e`，把传入指针 `r8` 所指的四个字清零；对应日志的四项 `onoff`。
- 两条 STRD 共写 16 字节，随后跳向共同的继续位置 `0x3dff9a`，没有在该处直接返回错误。

因此，未来即使观察到传输继续、请求成功或文件生成，也仍需检查 LUT 是否真正生效。这里没有证明就绪分支对应的任何图像是全分辨率 JPEG，也未识别全部状态枚举。

## 4. 可重复分析与测试

新增 [trace_lut_refresh.py](trace_lut_refresh.py)，只接受完整指纹匹配的原版 CP。它核对上述代码窗口、实际操作数重建的地址、描述符复制/提交、快照字段和未就绪分支；只输出地址及摘要，不输出原程序字节或机内载荷。

工具还检查回调入口到刷新调用的潜在控制流路径。实现区分直接条件/无条件分支、CBZ/CBNZ、调用、返回和未知 PC 写入；循环不会无限遍历，间接跳转和跳转表不会猜测。**它不求解分支条件，并假定调用可返回，所以潜在路径不等于可满足的运行路径。** 原版分析窗口中找到一条 138 条指令的潜在路径，只作为结构证据。

新增 [test_lut_refresh.py](tests/test_lut_refresh.py) 的 9 项合成测试，覆盖条件分支双出口、宽/窄无条件分支、回退循环、返回/间接跳转/跳转表停止、调用返回假设、缺失/重复指令、非指令边界及错误指纹拒绝。特别覆盖 Capstone 将条件分支报告为写 PC 的情形，防止错误截断路径。测试不嵌入 Sony 指令片段。

运行方式见[研究说明](README.md)，本地报告为忽略目录中的 `research/output/lut-refresh-v2.json`。三个运行/照片/设备证据标志仍为 false；实际测试命令及结果记在 [plan.md](../plan.md)。
